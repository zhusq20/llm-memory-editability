# bioS-Work 开发实验：失败归因与表征诊断（2026-09-26）

这是实验协议 v2.3 的符号开发分析。核心观察是：**直接修改成功并不保证公司默认查询正确传播；个人例外更新暴露了实际城市与公司默认城市的混淆。局部保持损伤进一步压低联合达标率。** 这些是保存预测支持的失败模式，不是已识别的完整因果机制。

## 覆盖、核验与比较口径

- 8/8 条完整学习轨迹，每条 13,280 步；2 个世界 × 2 个初始化 × SA（结构先行）/AS（事实先行）。
- 两个窗口的 256 个编辑执行全部完成，每例 512 步，逐条从保存的自由生成预测重算 E、D 和保持分层，并核验全部 2,816 个预定编辑检查点的联合判分。
- 中间窗口为零起算 3–5 层，早期窗口为 0–2 层；早期窗口属于探索性补充。FT-All 不受窗口限制，两窗口对应的 32 对终点预测及 NLL 完全相同，不能视为独立重复；去掉重复配置后为 224 个案例配置，仍共享仅 8 个旧模型。
- FT-MLP、FT-All 每种课程/更新/窗口有 8 例，来自 2 世界 × 2 初始化 × 2 支持集；FT-Down 和三种分支各 4 例，只用支持集 0。分支收益必须与支持集 0 的无分支 FT-MLP 配对，不能与其全部 8 例平均值相减。
- 联合标准：根默认值全部正确、成员更新 ≥95%、必要派生查询 D ≥95%，未见保持池各分层损伤 ≤1%，其中第 2 层的基础事实与派生查询分别满足门槛。全文的达标比例是**512 步终点**；曾经达标另列。
- 旧知识匹配仅 3/4 对通过。世界 1、初始化 1 的 SA/AS 派生准确率分别为 100%/99.4629%，相差 0.5371 个百分点，超过预定 0.5 门槛。总体保留这对运行，匹配子集单列；不因编辑结果排除种子。

逐案例分母、失败交集、完整曲线、共同已知保持集、初始新答案 NLL、完整阈值敏感性网格和逐输入结果索引均在 `results/bios-dev-v1/failure-analysis-20260926/`。可审查的紧凑表保存在 [development-artifacts](development-artifacts/)。不将 256 个执行当作 256 个独立模型，不对两个开发世界声称确认性显著性。

## 分方法、分更新类型的终点结果

下表使用预定中间窗口；E/D 为每例内部准确率后等权平均，括号中是联合达标例数。所有 FT-MLP 和 FT-All 的根/成员均为 100%，FT-Down 的细分值见完整 CSV。

| 方法 | 课程 | 一致更新：E / D / 联合 | 个人例外更新：E / D / 联合 |
| --- | --- | --- | --- |
| FT-MLP | AS | 100% / 99.48% / **5/8** | 100% / 48.83% / **0/8** |
| FT-MLP | SA | 100% / 83.72% / **0/8** | 100% / 40.23% / **0/8** |
| FT-All | AS | 100% / 88.54% / **3/8** | 100% / 38.41% / **0/8** |
| FT-All | SA | 100% / 94.27% / **1/8** | 100% / 43.88% / **0/8** |
| FT-Down | AS | 100% / 96.61% / **0/4** | 99.46% / 51.30% / **0/4** |
| FT-Down | SA | 84.14% / 47.66% / **0/4** | 48.12% / 16.41% / **0/4** |

**FT-MLP：一致更新主要受局部保持约束，例外更新主要受传播约束。** AS 的一致更新 8/8 通过 E 和 D，剩下 3 例全部只因 U 不通过。SA 的一致更新有 6/8 不通过 D、5/8 不通过 U，两类有重叠。两课程的例外更新都把全部直接目标学对，但 D 均 8/8 未达标；其中 AS 有 4/8、SA 有 5/8 同时不通过 U。

**FT-All：开放全参数并未消除传播问题，也不始终优于局部编辑。** 一致更新中，AS/SA 分别有 3/8、3/8 传播未达标，2/8、6/8 保持未达标。SA 的平均 D 高于 AS，与 FT-MLP 的课程方向相反；因此不能概括为“事实先行对所有编辑方法都有优势”。个人例外两课程仍均 8/8 传播失败。仅由 E 和回放提供的信息，即使全参数可动，也未形成可靠的默认/实际关系区分；这不能解释为模型容量不足。

**FT-Down：SA 在所测单层路径上连直接拟合也困难。** SA 的两类更新各 4/4 未通过 E；AS 两类各 4/4 通过 E 门槛，但每例都至少有一层保持损伤超限。全部 FT-Down 的固定前缀特征变化为 0，两窗口终点的层内校准最大绝对误差为 5.10×10⁻⁶，说明输出投影的局部线性关系成立；它并不保证后续自由生成、传播或保持成功。换成完整 MLP 或全参数后直接更新成功，支持“该局部更新路径受限”的解释，不能据此声称不可表示。

**早期窗口没有统一修复。** FT-MLP 的一致更新，AS 为 E=100%、D=84.77%、2/8 联合达标，SA 为 E=100%、D=89.06%、1/8 达标；个人例外 D 分别为 37.89%/40.62%，均 0/8。早层改变了课程相对表现，但不解除例外传播瓶颈；不能按某一格最好表现事后选层。

## 传播到底错成了什么

D 查询的正确答案始终是“人员雇主的默认工作城市”，不是“该人员实际工作城市”。个人例外更新将每家公司的 30 位原非例外人员均分成两组：15 人实际城市等于新默认，15 人实际城市与新默认不同；两个更新类型的公司默认目标完全相同，D 均未进入编辑监督或回放。

中间窗口 FT-MLP 的例外结果：

| D 子集 | 每课程分母 | AS 正确率 | SA 正确率 |
| --- | ---: | ---: | ---: |
| 更新后实际城市等于默认城市 | 360 | 311/360 = **86.39%** | 232/360 = **64.44%** |
| 更新后实际城市不同于默认城市 | 360 | 44/360 = **12.22%** | 63/360 = **17.50%** |
| 保持原个人例外的人员 | 48 | 20/48 = **41.67%** | 14/48 = **29.17%** |

这些分母是 8 个案例 × 各自固定查询数量的描述性汇总，不当作独立重复。AS 的 393 条 D 错误中，314 条（79.90%）输出了错误的个人实际城市，5 条仍输出旧公司默认值，74 条输出其他错误值。SA 的 459 条错误中，222 条（48.37%）输出个人实际城市，174 条停留在旧默认，63 条为其他值。没有未终止生成造成的 D 错误。

同样的错误也出现在 FT-All：AS 273/473、SA 250/431 的 D 错误是用个人实际城市代替公司默认。这说明“直接事实已更新，但公司默认关系未被可靠区分”比单纯未拟合 E 更符合预测证据。该错误模式支持关系复用/捷径的机制线索；仍不能仅凭答案相同证明具体内部路径。

## 保持损伤、时间轨迹与分支

U 的门槛作用于每个未见分层，不能用整体 U 接近 100% 替代。目标公司旧例外只有 1–2 条未见已知事实，错 1 条就是 50%–100%；同公司其他属性有 95–96 条，错 1 条至少是 1.0417%，已经超过 1%。这是真实的预定离散判分，不具有 1% 的精细分辨率。

中间窗口 FT-MLP-AS 一致更新的 3 个联合失败，全部是同公司其他属性层超限，损伤涉及出生城市与雇主；并非旧个人例外被统一抹掉。SA 的额外损伤更多落在其他公司的默认/实际工作城市。逐案例保存各层已知数、破坏数，并单列回放见过的事实及两课程共同已知的同一保持集合；没有让修复抵消破坏。

保持上限敏感性也支持这一分解：固定 E/D 的 95% 标准，中间窗口 FT-MLP-AS 一致更新在损伤上限 0%/1%/2%/5% 下分别通过 0/5/6/8 例；SA 分别通过 0/0/2/2 例。放宽保持阈值可解除 AS 的小分层瓶颈，却不能解除 SA 剩余的传播失败。完整 3×4 阈值网格保留，不据此改写主判分。

全部个人例外案例在预定检查点中都未曾联合达标。中间窗口 FT-All 一致更新，AS 曾达标 4/8、最终 3/8；SA 曾达标 3/8、最终 1/8。AS FT-Down 一致更新曾达标 1/4，终点回落至 0/4。因此不能选中途最好点作为固定预算结果，继续训练也不保证单调改善。

三种分支各增加 25,600 个参数，零初始化检查与旧世界身份变异检查通过。与**同一支持集 0**的 FT-MLP 配对，中间窗口的三种分支均未改变 E/D 准确率与联合判分；输出 NLL 已改变，部分背景查询也改变，因此不能把相同均值误判为分支没有接入。早期窗口的单例 D 变化最多 1/96（1.0417 个百分点），没有一致的联合达标收益。独立方向并未显示优于共享或随机方向的可重复行为证据；冻结原模型、仅训练分支的诊断仍未运行。

## 补齐的表征诊断

本次新增 24 个 GPU BF16 测量（8 个模型 × 第 2640、5280、13280 步）及缺失的 4 个 CPU FP32 终点测量，使 CPU 终点覆盖达到 8/8。每个测量包含 8 个预定 recipient 公司 × 8 层 × 5 种干预，共 320 个条件；合计保存 10,240 个条件，CPU/GPU 对同一模型的复查不增加独立重复。全部保存 2048 个实际城市查询的全层 z，以及固定 128 人、3 个 token 位置的 x/z/h；权重对应原始检查点。

新增 GPU 干预同时记录完整答案生成及原答案正确率，避免把下一 token 概率当作实际编辑成功。另完成全部 8 个旧模型的 E/R 测量：支持集 0、1 × 一致/例外 × 第 2、5 层（层号从 1 起），共 64 条几何/梯度记录。只使用 E 与允许回放的 R，不把 D 或未见保持 U 的特征用于此诊断。

**终点的早期响应存在课程差异，但不是纯粹的公司语义。** 下表为第 1 层 donor 均值替换后的 donor 答案概率变化，单位为百分点，来自 GPU BF16：

| 世界/初始化 | 课程 | 同公司非例外 | 同人独立出生城市 | 无关公司 |
| --- | --- | ---: | ---: | ---: |
| 0/0 | SA | +13.369 | +0.954 | +0.901 |
| 0/0 | AS | +79.492 | +37.577 | +6.914 |
| 0/1 | SA | +89.456 | +44.156 | +32.998 |
| 0/1 | AS | +86.970 | +9.824 | +8.863 |
| 1/0 | SA | +0.060 | +0.078 | +0.098 |
| 1/0 | AS | +70.106 | +14.781 | +7.204 |
| 1/1 | SA | +0.001 | +0.002 | +0.000 |
| 1/1 | AS | +71.236 | +17.281 | +17.885 |

AS 的“目标响应 − 独立属性/无关公司响应均值”在四对模型中均较高；但目标响应本身并非每对都更高，世界 0、初始化 1 的 SA 也很强，并伴随严重外溢。该 SA 模型的完整 donor 答案生成变化分别为同公司 +93.75、独立出生城市 +50.00、无关公司 +34.38 个百分点，确认外溢不只是置信度的微小波动。不能将课程直接命名为“高/低共享”，也不能将公司均值视作已验证的纯公司知识。

**阶段差异不等于终点机制。** 第 5280 步、已经等曝光时，SA/AS 的第 1 层目标响应均值为 +20.34/+8.53 个百分点；共同巩固后变为 +25.72/+76.95。第 2640 步两课程仍接触不同信息，只描述轨迹，不作等信息比较。终点中间窗口中心第 5 层的同类响应均值仅为 SA +0.0024、AS +0.2123 个百分点，远弱于第 1 层；当前公司均值候选方向本身不足以解释中间层编辑差异。

**对照和精度复查。** 同答案 donor 与等范数随机方向对原 donor 城市的响应很小；错误 donor 对这个特定答案的响应也小，但 GPU 生成结果显示它仍可能破坏独立属性，不能把“没有转向原 donor 答案”解释成“没有作用”。消融结果与所有层、所有对照均保留。8 个终点在确定性干预下，CPU/GPU 的逐模型、逐层、按 recipient 平均指标最大绝对差为 0.092 个百分点；主要现象不是两种精度造成的。随机方向使用 CPU/CUDA 各自随机流，未冒充逐方向配对复查。

![阶段与终点全层诊断](../results/bios-dev-v1/failure-analysis-20260926/organization-stages.png)

**激活接近与目标方向必须分开看。** 在同公司、同关系、同旧答案的人员中，第 5 层例外更新的跨新答案组 z 余弦均值为 SA 0.609、AS 0.835，AS 反而更相近。实际两 token CE 对完整前缀 MLP 输出 h 的梯度余弦，在同新答案组为 SA 0.875、AS 0.888，跨新答案组降到 0.323/0.308；负余弦对比例仅 0.074%/0.056%。这是更新方向一致性降低，不能概括成普遍反向梯度冲突；更不能仅凭高激活相似度判断编辑难度。E 到回放 R 最近邻余弦均值为 SA 0.631、AS 0.828，也不直接等价于实际保持损伤。

独立分支在相同公司/关系/旧答案内的归一化身份变异确实较大：中间窗口 SA 的独立/共享/随机方向均值为 0.823/0.331/0.312，AS 为 0.514/0.120/0.181。但这些操作检查没有转化成可重复的编辑收益。该结果限制了“增加独立方向即可解决例外更新”的解释，冻结主干的分支实验和未见世界预测仍是独立未完成项。

## 可解释范围与下一步

预定匹配子集仍保留相同主要模式：中间窗口 FT-MLP 的 AS/SA 一致更新分别 4/6、0/6 联合达标，D 为 99.83%/90.97%；两课程例外更新均 0/6，D 为 48.61%/42.53%。这说明观察并非只由那一对轻微知识不匹配驱动，但匹配属于课程之后的条件化，不把它当作完整总体的因果证明。

目前支持三个不同层次的结论：E 拟合困难集中在所测 SA 单层 FT-Down 路径；例外更新的核心失败是默认/实际关系传播混淆；保持损伤集中在少量局部属性，压低联合通过率。公司均值干预和梯度诊断提供线索，尚不足以识别完整中介机制。

下一轮最有针对性的开发验证是：固定支持集和预算，单独检验默认/实际关系区分是否能恢复 D，同时保留传播评价隔离；按原协议运行共同学习率与保持权重敏感性，避免把单个超参数的不适配当作稳定组织差异；用冻结主干的分支诊断检验独立方向是否具有可用的身份控制能力。改变监督信息必须记录为新的开发条件，不能并入本批次。本文没有执行这些新增训练，也没有运行自然语言、Qwen、SmolLM2、AlphaEdit 或确认性实验。

## 复现与产物

```bash
# 复核已保存的 256 例，不重训
.venv/bin/python -m llm_memory_editability.bios_analysis
# GPU 编号按实际资源指定；本次使用物理 GPU 4 的 UUID
CUDA_VISIBLE_DEVICES=4 .venv/bin/python scripts/run_bios_diagnostics.py --device cuda
.venv/bin/python scripts/run_bios_diagnostics.py --device cpu
CUDA_VISIBLE_DEVICES=4 .venv/bin/python scripts/measure_bios_edit_geometry.py
# 使用 configs/report-environment-dev-v1.json 所记的绘图环境
python scripts/report_bios_diagnostics.py
python scripts/summarize_bios.py
```

新诊断记录 checkpoint 哈希、源码哈希、精度、实际耗时；原始权重和旧实验结果保留。历史 CPU 初始化 0 记录没有新增的运行元数据，未补造历史耗时；GPU 复测对同一权重记录了完整来源。新添加的生成检查使用模型自己的首个预测 token 续生成 EOS，不读取正确答案前缀；E 梯度使用真实的两 token CE，教师强制仅用于损失诊断，不冒充自由生成成绩。
