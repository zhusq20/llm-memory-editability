## 1. 最新目标与应当解释的问题

目标是让实际部署的模型学会新知识后，能够在自然问题中调用、与已有知识组合，并在事实变化后使用新的后果，同时保留其它能力。论文核心仍是：**知识在哪里、推理在哪里、二者怎样连接。** 会答、能组合、更新后能用和架构分别需要端到端证据。

方法研究要说明一个算法为什么有效：它增加了哪些用途的训练信号，改变了哪些参数或状态，怎样把读出的内容接入现有推理。原生记忆架构研究要进一步问：记忆写在何处、怎样跨深度读取、后面推导出的新实体能否再次查询，以及更新的是会话状态还是可跨请求保留的知识。

自然多跳任务上的整体改善值得研究，不必先完成一套逐级因果干预。若随后把改善归因于地址、内容或深度，再补充能区分该解释的轻量测量。长上下文检索、普通语言建模或单跳掌握率不能替代新知识的多用途和更新传播结果。

## 2. 旧实验能支持什么，不能代替什么

项目已有 M3、E3 和测试时上下文蒸馏实验有解释价值，但不能当作下述原论文方法的复现或普遍结论。

- **M3** 是本项目的离线上下文蒸馏配方，采用自己的问句、生成、优化和保持设置。它的跨用途失败支持“这个写入配方怎样工作”的分析，不能据此说 Prompt Distillation 的原方法、LoRA 或上下文蒸馏一般无效。
- **E3** 的逐事实秩一增量、隐藏状态对齐和顺序写入不等于通常的联合 LoRA 训练。现有 E3 对齐使用 teacher-forced 回复位置，其中隐藏状态已经能看到输入的回复 token；它不是实体入口的答案出现前对齐。
- **小模型 TTCD 与原子 CE 的差别** 是同一受控任务上的算法观察。它不能替代自然文档上的 PD、SEAL 或 Cartridges 原实验。
- **已有成功结果应保留。** 用途练习已改善未练事实的使用，邻居保护已改善连续写入后的组合保持。下一步的问题是自然部署中的可复用条件，不能通过重新描述任务把已完成结果当成空白。

具体证据入口：[M3 开发比较](../results.md#knowledge-read-interface-development-v1)、[E3 与用途比较](../results.md#knowledge-read-interface-v2)、[用途练习](../results.md#use-adapter-development-v1)、[邻居保护](../results.md#neighbor-protection-development-v1)。

## 3. 优先借鉴和复现的算法

| 方法 | 原方法实际写什么、用什么信号 | 原论文已有证据 | 本项目的用途与复现边界 |
| --- | --- | --- | --- |
| **Prompt Distillation，PD** | 同一基础模型充当教师和学生：教师看文档，学生不看文档；在合成回复的预测位置匹配教师分布。官方主要实现用 LoRA，覆盖 attention、MLP 和 lm_head | HotpotQA 从每段文档分别合成单跳 QA，再测原多跳问题；PD 与相同材料上的 SFT 比较，提供最直接的自然知识注入与组合证据 | **第一优先。** 复用作者数据组织、提示及 KL/CE 比较，再改变参数范围。小样本、新 Qwen 或优化设置改变属于原方法的受控适配，不能称完整复现原表格。[论文](https://arxiv.org/html/2412.14964v2)、[官方代码](https://github.com/kallekku/prompt-distillation) |
| **Context Distillation** | 教师看到额外上下文，学生不看到上下文。Snell 等蒸馏指令、推理和样例；Padmanabhan 等用实体定义及实体续写构造迁移集，在实体出现后的 token 上匹配分布 | 前者有任务指令、算术推理和 Text-to-SQL；后者测试实体推断和 ECBD 等知识使用 | 适合检验“迁移集覆盖了哪些用途”。Padmanabhan 的实体续写比只问一个原子问题更宽，但不是充分的自然多跳或更新传播证据。[Snell 原文](https://arxiv.org/abs/2209.15189)、[Padmanabhan 原文](https://arxiv.org/html/2306.09306)、[官方代码](https://github.com/shankarp8/knowledge_distillation) |
| **SEAL** | 模型生成自己的学习材料，内层用临时 LoRA 适应；外层根据实际适应后的任务收益，用 ReSTEM 更新生成自编辑材料的策略 | 有知识吸收和适应任务，直接把“生成什么学习材料”与后续收益连接 | 适合研究用途和推论数据为何帮助写入。只生成一些推论再 SFT 是借鉴内层；缺少外层学习便不是完整 SEAL。[论文](https://arxiv.org/html/2506.10943v2)、[官方代码](https://github.com/Continual-Intelligence/SEAL) |
| **Cartridges** | 冻结基础模型，训练可复用的 KV 前缀；通过文档教师的多轮 self-study 蒸馏学习 | 有自然文档推理及独立训练 cartridges 的组合；官方实现支持 Qwen3 | 最相关的独立存储参照：知识可保存在推理时读取的 KV 中。它写的不是 MLP 参数；把 KV 改成 LoRA 后不能再叫原方法。[论文](https://arxiv.org/html/2506.06266)、[官方代码](https://github.com/HazyResearch/cartridges) |

**当前四臂为 PD-LoRA、SFT-LoRA、SFT-full 和 SFT-down。** PD-LoRA 对 SFT-LoRA 比较作者两套配方：文档、合成问题和可训练范围相同，但回复分别以温度 1.5 和 0.25 生成，损失分别为教师分布 KL 和硬标签 CE。因此这不是只改变损失的消融，收益不能唯一归因于软标签。后三臂使用相同 SFT 回复和 CE 目标，回答收益是否依赖可训练范围；四臂不构成 KL/CE 与参数范围的完整交叉比较。参数数量、优化难度和每步计算不同，不能仅凭同一步数宣称效率公平。

本轮采用作者原 CSV 中的 32 个案例，合计 312 段文档；其中一题只有 2 段，保留该题及原始覆盖，不换题补成 320 段。每段 30 条合成问答，共 9,360 条；四臂各 5 轮、11,700 次参数更新。LoRA 使用原配方的高秩 1,024 并包含 lm_head，实际可训练参数和显存以运行清单为准，不能默认其成本很小。基础闭卷模型与文档在场教师是无更新评测对照，不是训练臂。这是原方法的小规模适配比较，正式启动和完成状态以批次记录为准。

应保留基础闭卷模型、文档在场教师，以及所有写入臂的自然多跳生成结果。这32个HotpotQA案例包含既有自然事实，不能保证基础模型此前未知；原本正确和原本错误的题分别报告，不能把整体改善直接称为新事实学习。生成学习材料时只提供单段文档，不提供评测多跳问题及其答案；教师有文档、学生无文档。当前排除与评测问句完全一致的合成问题，这不证明所有语义相近用途均未出现。**本轮主评估是留出的 HotpotQA 问题与旧能力保持，尚非对同一事实的全面多用途评测，也没有测试事实修改后的更新传播。** 保留生成文本及评分规则；原论文的 judge、包含匹配与规范 EM/F1 回答不同问题，不能互相冒名。

另加固定的 **teacher-target-fit** 辅助诊断：每个案例取 `train.jsonl` 中第一条问答，共 32 条；PD 使用该条的 `pd_answer`，SFT 使用 `sft_answer`，更新前后使用相同样本和目标。在闭卷提示下逐 token 提供正确的教师回复前缀，记录每例平均负对数似然、下一 token 的贪心符合比例、有效目标 token 数及其中 EOS 数。它不重新生成、不读取评测真值、不筛题，也不用于早停。该指标只能说明对已生成训练目标的拟合，不能称真实单跳事实正确率或知识掌握证明；PD 本身优化的是完整教师分布，硬目标 NLL 也不是其训练 KL 的替代值。

这项比较首先建立方法有效性。即使 KL 胜过 CE，也不能立即断言它把内容写成了实体表示；即使 LoRA 与全参数接近，也不能说两者参数里的地址相同。参数特征和位置测量用来解释已经观察到的行为差别。

## 4. 六组原生记忆架构

表中“可再次查询”是对计算图的分析，表示存在计算通路，不表示论文已经验证了新事实的多跳调用。Qwen 迁移成本是工程判断。

| 架构 | 持久性与写入 | 读取地址和层位置 | 各层能否复用、能否查询后续实体 | 已验证任务 | Qwen 迁移成本与优先级 |
| --- | --- | --- | --- | --- | --- |
| **Memory Layers at Scale / Memory+** | 参数化 key/value 表；通常通过训练更新，推理时不会自动收录新事实 | 每个 token 的 hidden state 生成 query，稀疏选取条目，在若干 FFN 位置读取；24 层消融中 4/12/20 层组合较好 | 官方实现共享 **value 池**，各层 keys 和 query 投影独立。后层可以读同一内容；相同实体跨层触发同一条目仍需学习 | 事实 QA、HotpotQA 和规模扩展；没有受控的新事实修改后多用途传播 | **研究优先级 1。** 侧支小记忆表属中等工程量；建立可用读写接口仍需训练。原论文替换部分 FFN，保留 FFN 加侧支属于扩展。[论文](https://arxiv.org/html/2412.09764v2) |
| **Engram** | 静态 n-gram 参数表，通过训练更新；CPU offload 不等于可在线编辑的事实库 | 输入 token 的 n-gram 经哈希定址，hidden state 控制融合门；主要模型在层 2/15 接入 | lookup index 由实际 token 决定，不能仅凭隐状态中刚推导出的实体改变地址；若把实体生成成后续 token，才有新的查表机会 | 知识、推理和长上下文基准；没有独立事实更新传播 | 侧支实现相对容易，但对隐式第二次实体查询帮助不直接，暂不优先。[论文](https://arxiv.org/html/2601.07372v1) |
| **Titans / TTT layers** | 序列内快权重，由自监督误差在线更新线性模型或 MLP。Titans 的静态 persistent tokens 与在线记忆是两件事 | 各层用当前表示读写自己的快状态；Titans MAC 还在 attention 后使用变换后的表示再次读取 | 后续 token 可再查；Titans MAC 也提供同段再读通路，但没有自动形成跨层统一实体地址。跨会话保存恢复须另行定义 | Titans 有 BABILong 跨事实推理；TTT 主要是语言建模及效率。没有明确的持久事实修改传播实验 | 原生快记忆备选；替换 Qwen 计算和学习快写入规则成本高。[Titans](https://arxiv.org/html/2501.00663v1)、[TTT](https://arxiv.org/html/2407.04620v1) |
| **Memory Mosaics / v2 / MM+** | 上下文关联记忆追加观测 key/value，另有离线学到的持久参数；二者不能合称在线参数更新 | 使用学习到的上下文特征，key/query 使用相同特征形式；不同记忆层交替计算 | 后层有继续查询机会，但各层记忆并不自动成为共享实体事实表；跨文档缓存要区别于永久参数知识 | 原版有因素组合任务；v2 的“new-knowledge storage”是 RULER 多文档 QA；MM+ 强化跨文档上下文使用，尚非事实更新传播 | 适合原生上下文学习参照；改造 attention 和特征提取成本高。[v2](https://proceedings.neurips.cc/paper_files/paper/2025/file/3767842e2ebee900236f534855aa2c36-Paper-Conference.pdf)、[MM+](https://arxiv.org/html/2610.20782v1) |

## 5. 从实际计算出发：算法为什么可能有效

### 写入后的迁移由地址、内容和后续计算共同决定

考虑 Transformer 中某个 MLP 的输出投影 `m = W_down a`，其中 `a` 是上游归一化、门控和非线性之后的真实激活。普通 SGD 的一步更新满足

`ΔW_down = −η Σ_p δ_p a_pᵀ`，其中 `δ_p = ∂L/∂m_p`。

这是该参数的梯度恒等式；共享参数须对各次执行求和。冻结这些输入激活后，更新对另一地址的直接模块作用为

`Δm(a′) = −η Σ_p δ_p ⟨a_p, a′⟩`。

完整模型中的一阶作用还要经过 `Δf(u) ≈ J_θ f(u) Δθ`；Jacobian 包含残差、归一化、attention、其它 MLP 和输出投影。该局部式不把整个 Transformer 化约成一张线性记忆表，也不保证新用途上的作用有利。

由此可以提出三个可验证问题：新用途是否触发相关地址；写入方向是否提供后续计算需要的内容；读到该内容时是否还有可用的计算深度。**这些是条件和研究问题，不是“所有答案监督都只能记住答案”的证明。** 广泛的训练用途、已有模型能力和不同监督目标都可能让最终答案损失形成可复用知识。

### KL、用途数据和参数范围分别改变什么

在温度 1 的单个预测位置，前向 `KL(p_teacher || p_student)` 对学生 logits 的梯度为 `p_student − p_teacher`；硬标签交叉熵对应 `p_student − one_hot(y)`。教师分布改变误差信号，合成问句与续写改变输入地址及使用情境，两者可以共同改变迁移。“都监督答案”不足以推断两者等价。本轮先比较作者整体配方；若需要单独归因软标签，才另行固定同一组回复比较 KL/CE，不能把当前回复温度也不同的两臂当成该消融。

LoRA 改变允许的参数更新子空间，并不自动把地址变成实体或限制在某一层。全参数、LoRA 和 down-only 的比较应核对实际可训练模块、学习率、初始函数和优化预算；结果接近说明端到端行为接近，不能单独证明内部机制相同。

### 多深度可读与在线更新是两个不同设计轴

设记忆模块在层 `l` 读取 `r_l = R_l(q_l(h_l), S)`。若某个中间实体只在更后层才形成、它需要的关联只在更早的读取处可用、相应结果又没有提前传到当前表示，那么本次前向无法让已结束的那次读取重新使用新实体。解决办法可以是在后续层再次访问存储、保留已读出的相关信息，或使用新的计算轮次。条件缺一时，不能仅凭“层单向”断言组合必然失败。

Memory+ 提供跨深度共享内容，但还须训练地址对齐；Engram 提供确定的文本地址，但隐藏实体不能直接改写索引；Titans/TTT/Hope 提供在线状态或参数更新，但不自动保证更新后的知识跨用途可读。这解释了为什么“有记忆”“能在线更新”“能多跳使用”需要分别测量。

## 6. 本轮结论与后续判读

1. **PD-LoRA、SFT-LoRA、SFT-full 和 SFT-down 四臂已完成，先复核已保存回答的语义。** 使用作者自然文档与单跳训练、多跳评价的关键设计，明确小规模和模型适配差异。保留预定EM/F1，另列格式与实质错误；先确认自然问题上的算法收益，再用地址、内容和深度解释差异。
2. **Memory+ 是架构首选研究对象。** 最有价值的扩展是一个持久内容池在多个深度可被再次读取；保留 Qwen 主体、增加小侧支表是候选设计，不是已验证方案。共享 keys、训练读写接口或改变写入目标都应单列，不能归功于原论文。
3. **Hope-Attention 是持续适应的第二候选。** 多时间尺度学习有实际预训练模型适配依据，但需要计入大规模适配成本，先核实关键实现与可用资源，不立即重训完整架构。
4. **Cartridges 保留为独立存储参照。** 它能帮助区分参数写入与可复用 KV 对知识调用的影响。Titans/TTT 仅在明确需要持续会话状态时提高优先级。
