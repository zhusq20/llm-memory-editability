# 连续新事实写入的最小消融

用户已授权实现、利用空闲GPU并行执行、独立重载和W&B云端核验。沿用已完成的 `ce-cross-sample-double-new-v1` 检查点、事实流、教师与评分；原批次及其冻结源码不修改、不重跑。此批为一个已观察世界、各架构一个初始化的开发证据。

## 问题与比较

固定Loop或DiscoLoop架构，比较原配方与三个单变量改变。普通Transformer原结果只作参照，不新增基础训练。每个新臂只改变下列一项：

|臂|改变|保持|
|---|---|---|
|lower-lr|Loop依次检查5e-6、2e-5；DiscoLoop依次检查2e-5、4e-5|逐事实新建Adam、theta0±0.0005元素截断|
|carry-adam|同一流跨事实保留Adam一阶矩、二阶矩和计数；新流重新创建|原学习率、原元素截断|
|no-bound|取消每次更新后的元素截断|原学习率、逐事实新建Adam|

原学习率Loop3.2e-4、DiscoLoop8e-5。所有臂保持每事实20步、Adam(0.9,0.999)、eps1e-8、weight decay0、梯度裁剪1、旧输出KL系数10及原20批旧原子/组合教师。仅更新唯一物理MLP参数；残差、归一化、attention、原生GELU和DiscoLoop通道不修改。FP32、eval、dropout0、关闭TF32；theta0是原300k检查点。无新组合监督、无新事实回放。

## 开发写入检查

只用原8对开发事实，固定顺序先全部A再全部B，反向流为整流倒序。每流16事实，每事实20步；每次仅读刚写入的当前事实，不查询开发组合或遗忘。保存全部32个状态及答案/EOS。每个候选必须有限、至少29/32当前事实答案及EOS正确、逐事实首末CE下降的中位数严格为正。lower-lr选择预定顺序中首个合格候选，至多两个；不可按正式组合或遗忘结果选学习率。其它臂只检查一个候选。候选/流之间均恢复theta0并清空Adam。

没有合格候选的臂保留失败的写入证据，完成独立开发状态重载和云端核验，记为不具比较前提，不启动正式流，也不把其缺失正式结果记为零。开发阶段优化计数单列，不冒充零训练。

## 正式流与评分

完整复用原32对/64事实、forward和reverse两流，配对间隔31个其它事实。流内参数持续；流间恢复theta0。每流1280步，每臂2560步。每事实后读原完整查询矩阵，另有共同基线，共129次读出、128个新增MLP状态；不重跑孤立对照，也不捏造孤立记录。正式结果不用来重选配方。

先报刚写入成功率，再报按后续事实数的遗忘、终点新原子保持、双新组合全量命中、两前提均正确的覆盖及联合/条件组合成功。共同原子前提子集与全量分开。旧知识同时报原子、七池及初始正确组合的保持。32事实对为bootstrap单位，两个顺序在对内平均，10,000次、seed2026101611；不能把流前缀当独立样本。参数更新记录每事实实际RMS/最大变化、theta0偏移、原区域边界饱和/越界、跨边界翻转和更新投影。

## 工程、审计及预算

每架构先在真实完整模型上比较原写入器20步与新基线写入器20步逐损失/全部模型参数精确一致，再检查跨事实Adam的2步A、2步B与恢复A状态后2步B精确一致，合计46工程步，全部恢复theta0。工程不查询正式结果。

开发状态和正式129状态均在独立新容器中重载；检查文件哈希、MLP及完整模型哈希、答案/EOS逐值一致，浮点评分容差1e-5，重新计算完整统计。carry-adam还保存/重载两个流终点的Adam完整状态，核对m/v/计数摘要；所有前缀记录实际计数，连续性由工程重放另验。审计不优化。

科学更新上限15,360；开发3,840，若两个低学习率臂均使用第二候选上限5,120；工程92；总优化上限20,572。新基础/outer/组合监督更新均为零。各阶段记录耗时、曝光、计算与资源。仅使用实际独占空闲GPU，每个阶段重新申请，外部占用则等待；CPU每臂独占4核、内存48g，不干扰其它项目。固定LM镜像、冻结444项父源码原字节及新增文件；原始失败不覆盖，不自动重做科学写入。

每个prepare/gate/audit-gate/science/audit阶段在线W&B记录，最终CPU核对finished状态、优化计数、完整result.json下载哈希。汇总也上传完整JSON并独立下载核验。科学完成、独立重载通过、W&B云端通过分别记载。原配方两条结果按哈希及原完成收据复用。

单因素改善支持该因素对本配方遗忘的因果贡献；无改善不能证明架构必然缺陷，也不能排除因素交互。低学习率可能改变写入强度，因此写入成功及CE变化必须一同呈现。
