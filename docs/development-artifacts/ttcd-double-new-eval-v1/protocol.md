# 两条新写事实的组合及连续写入保持评测

2026-10-15，用户明确要求补充“双新事实相互组合”，同时检查连续写入后早先事实与旧知识保持。本批仅新增评测，复用`ttcd-successful-base-v1`两臂固定10k终点；原训练、优化器、数据流、writer、原评测及冻结源码保持。当前实现与验证状态见[结果汇总](../../results.md#ttcd-double-new-eval-v1)，本协议在任何正式模型预测之前冻结。[配置](../../../configs/ttcd-double-new-eval-v1.json)。

## 核心问题与模型来源

比较single与stream外层训练，是否在同一A连续写入后更好地使用两条新事实，并保留早先写入的信息及未改旧知识。沿用[TTCD式(6)](https://arxiv.org/html/2608.01672v1#S3.SS1)的GPT/GELU适配，不称完整作者v9复现。无新增训练，也不训练/筛选更新后的两跳答案。

须待父批共同读取、能力保持门槛通过，且两臂原训练/重载/校准/正式评测/重放/云端核验均成功后，才申请GPU运行本补充评测，避免只有一张空闲卡时补充评测延迟另一臂原训练。失败保留并停止，不延长训练、不根据新增组合结果换模型或writer参数。共同阶段仍在GPU4执行时可做纯图准备和开发工程检查，不干预训练。

## 在模型预测前确定事实与真值

复用父面板全部32个evaluation目标键，均已排除在更正外层训练之外；旧原生事实/II回放依然可能包含这些键的旧答案。16 ID与16 OOD指原键是否有组合训练经历，并非旧原子事实从未学习。本次把32键完整配成16对，原类别II/IO/OI/OO各4对；同一键仅出现在一对中。

若两键为`(h,r1,old_bridge)`和`(b,r2,old_tail)`，分别写入`h r1 → b`与`b r2 → new_tail`，再独立查询`h r1 r2 → new_tail`。第一条新尾改为配对第二条的头；第二条沿用父面板原冻结replacement。第一条的新尾不能等于旧桥，第二条新尾不能等于其旧尾。原查询须在原图合法、未进入native II支持，原查询旧第二键须不在任何32个目标键中。原查询旧答案、只写第一条后的答案、两条均写后的答案三者互异，终点不等于两个头。

匹配只依图、原replacement与固定seed20261015，按剩余合法边最少的键递归匹配并缓存失败状态；没有模型准确率筛选。完整匹配不存在时停止，不能缩减事实或按预测重选。实际图有89个符合约束的有向候选，可完整覆盖32键。原64个U原子与64个U组合原样复用，排除所有32个目标键，真值始终保持。

逐时两跳真值依据实际写入历史：两条均未写或只写第二条，答案为原查询旧答案；只写第一条，答案为第二条旧尾；两条均写，答案为第二条新尾。只有两条均已写时才进入“双新组合”的主计分；没有闭合的链不计为遗忘。保存所有阶段的当前真值、最终新真值、答案/EOS、排名及分数。

## 写入与对照

两臂都从A=0开始，按同一32个父面板循环旋转顺序逐条写完32事实，每事实4次原TTCD局部写入。每次写入后读出全部已写事实及其原D、所有16条新新组合、全部32个目标原子、64 U原子和64 U组合。每个独立查询清空文本/KV，仅携带A；读出不得改变A或基础权重。

另保存A0、32条单事实状态以及16对各两种写入先后的独立状态。因此每对都有未写、只写第一条、只写第二条、两条正序、两条逆序五个参照。两条均写的独立对照避免把组合本身的失败与其它事实造成的干扰混为一项。

本批采用独立补充写入流。16条第一事实的新尾与原面板不同，不能直接复用原面板保存的A；原面板及其第二跳/再次更正评价继续完成并独立报告。

## 计分与保持

固定主结果为t=32时16对的等权双新组合准确率，答案和EOS均须正确。t=1…32全曲线、I/O分组与配对覆盖完整保留；t=8为次要读数。32个循环旋转不保证每对先后或t8闭合覆盖均衡，因此分开报告两种先后、两事实各自写入年龄、写入间隔与链闭合后年龄。孤立两事实的两种顺序均完整覆盖。

同时报告两原子各自和同时答对的比例、无条件组合率，以及“两原子均正确”子集的组合率和分母/覆盖；条件子集不替换全量主结果。较早事实保持同时给全量年龄准确率，以及仅在该事实刚写入时答对的子集后来保持率。组合保持以两条刚写齐时的成功为参照，报告同样的分母与覆盖。原有知识同时给U原子/U组合的A0和写后准确率、A0原正确子集的保持率，避免把终点A0已有退化算作连续写入干扰。

一张已观察图、一个模型初始化、16固定事实对；旋转及时间点均是重复测量，不是独立世界。普通旧世界回放仍在父训练中，因此不称无回放持续学习。新知识指这些键的新更正值，未检验新实体词表扩展或无限流巩固。

## 执行与独立审计

每臂1089状态：A0一次、单事实32次、独立两事实32次、32顺序×32前缀1024次。每A为9437184个FP32元素约36MiB，约38.3GiB/臂；新增两臂约76.6GiB，与父评测合计约169GiB，启动前至少200GiB可用持久空间。CPU单臂4核、内存96GiB，独立CPU32–35/36–39，GPU4/7优先并允许其它物理空闲卡，独占GPU锁，不共享或抢占。

只用固定LM镜像及`docker --context lm-memory`。新批目录`/ossfs/workspace/llm-memory-editability/ttcd-double-new-eval-v1`保存新的source、父source-v2 manifest哈希、面板/源码/配置哈希、调度记录、全部失败、预测与A；父所有科学文件逐字节复制，不改CODE_FILES。W&B沿用团队zhusq20、项目llm-memory-editability。

固定镜像CPU契约包含默认父检查点身份加载及独立CLI准备/评测/审计，使用明确标记的小型工程夹具。正式评测前，每臂在取得独占GPU后先执行真实300k基础权重的开发预检：仅两条calibration事实、两种写入顺序，保存/重载/从零重写均逐值及逐token/分数一致，实际CUDA前向/反向/同步正常，骨干不变、科学更新0、正式题查询0。预检失败停止该臂，不把原共同训练GPU拿来共享，不放宽阈值。
