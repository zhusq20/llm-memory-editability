# 关闭 dropout：state-MLP 单因素配对

2026-10-22 用户明确授权找空卡执行一条关闭 dropout 的实验，其他配方和初值不变，复用现有对照，不影响运行任务。此前的配方设计冻结件保持原样；本协议记录新增的执行授权。

## 问题与历史

原 state-MLP 的四跳组合准确率在训练损失较低时仍持续下降，已有检查点诊断显示第二跳调用形成退化。当前假说是每次分段重新采样输入及层内 dropout 会改变循环状态与输入之间的接口；尚未证实根因。Huginn/Ouro 的原材料及旧零 dropout 任务的核对见[已有方案](../loop-dropout-recipe-design-v1/design.json)。本次是已有方向的配方消融，不是新架构或独立确认。

## 唯一训练改动

原 state-MLP 冻结源码整个复制，不更新其模型、数据或训练循环。仅将 `attn_pdrop`、`embd_pdrop`、`resid_pdrop` 从 0.1 设为 0。不是用评测模式代替训练。768维、12头、16维状态打分器、完整数据、初始权重、样本顺序、随机段深、分段答案/EOS监督、状态 detach、AdamW、学习率、权重衰减、EMA、batch512 全部保留。完整初始模型须逐 tensor 等于原 state-MLP 的第0步，SHA256 为 `70289bd6aa675caded73065118b76b917282dcb81b040c2ef5ef7d1d69cc3640`，不只核对 backbone。

按前一轮方案先执行500000更新，另有32步工程短测；**学习率依然按1500000步的原时间轴计算**，不在50万步提前衰减到终点。仅通过原训练循环的评测节点上限截断执行。原对照不重启、不续训、不复制训练，其自己的150万步流程继续。

## 预定评价

主要看参数EMA、R8的B四跳全词表答案准确率，在匹配的0、1000、8000、16000、32000、64000、128000、256000、300000、400000、500000步比较完整曲线，报告50万步减25.6万步的百分点差以及固定50万步终点。保留B两/三跳、A留出、原子、全部11组面板、R4/R8及raw R4，不按最优检查点选择结果。终点复用原R1–32深度评测及33份预测文件的独立进程逐项重放；新适配器仅把终点审计常量改为50万，训练LR horizon仍为150万。

关闭 dropout 也可能加重组合过拟合；即使曲线稳定，也不能归因于其中某一处 dropout 或宣称已解决大模型训练稳定性。一次旧世界/旧初始化的配对不算独立世界或种子确认。运行完整150万步不在本次先行预算内。

## 执行与恢复

只使用LM固定镜像及 `lm-memory` Docker，每阶段独立容器，2CPU（84、85）、16GiB内存、独立临时目录与输出。输入只读，源码采用create-copy-start并在容器内root所有、0444/0555，避免NFS私有父目录绑定失败，不改变旧目录权限。在线W&B使用zsqzz/llm-memory-editability，本地私有凭据只在内存传输至新容器，不从旧运行容器提取。

本机该用户所有批次合计最多4张卡，不共卡。显存/利用率、实际CUDA进程、两个Docker上下文的显式GPU预约（包括created容器）都参与检查，连续两次空闲、创建前与启动前再次核对。旧Loop队列动态资源池及原state-MLP的GPU0保留至各自完整评测/云端结束，不抢阶段空隙；GPU3历史137原因未明，本队列排除。找不到卡则仅持久等待，不创建GPU预约容器。

固定镜像CPU契约与格式检查通过后才提交等待控制器；实际空卡到来后仍须通过完整尺寸CUDA初值/梯度检查、零dropout的train/eval及分段重放一致、32步短训练和独立重载，之后才允许科学训练。失败不自动重试；本队列创建但从未启动的容器仅在严格身份/零PID/零启动时间核对后经Docker API移除，保留失败记录，避免占用旧队列卡。

持久目录为`loop-dropout-development-v1`；仓库`results/loop-dropout-development-v1/runtime`是入口。恢复先读`freeze.json`、`engineering/cpu-checks.json`、`controller-process.json`、`controller-state.json`及实际容器。新控制器不会改写或重启任何旧控制器。
