# invariant：重复训练、换数据与测试时深度扩展

2026-10-21，用户明确要求“测测这个方法的稳定性/是否 data sensitive / 能不能做深度扩展（InfiLoop 的相同目标）”。本批据此授权；不重启已完成批次。

## 问题与关键比较

保持当前 invariant 架构、答案/EOS 监督和 150 万步配方。每个新条件都配对训练 invariant 与常数打分的 ema；两者共享骨干初始化、样本流、dropout 和循环数抽样。原世界的旧终点作为已观察参考，不选择最好检查点。

| 条件 | 改变 | 保留 | 新训练 |
| --- | --- | --- | --- |
| init-1、init-2 | 骨干及打分 MLP 初始化 | 原数据、样本流、dropout、循环抽样 | 各两臂 |
| new-world | 重新采样置换关系图及查询 | 原初始化与训练配方、数据规模 | 两臂 |
| many-to-one | 将 new-world 的双射关系换为随机确定函数 | 查询、图大小、训练/测试划分、初始化与配方 | 两臂 |

共八条新训练，各 1,500,000 更新，总 12,000,000 更新；32 步工程短训另计。两次新初始化加已有初始化构成三次初始化比较，不能当成三个独立数据世界。换数据后从头学习该数据的原子知识；不拿一个未学过新知识的旧模型直接猜新答案。

many-to-one 允许多个实体映射到同一实体，打破旧数据每种关系必须是置换的条件。固定关系序列的答案可能不均匀，必须报告常数答案及仅知道关系序列的最佳猜测准确率，同时逐条核验原子路径和划分。比较仍以完整查询和 invariant−ema 配对差为主；另报必要原子事实均能答对的覆盖率和条件准确率。它测试关系分布变化，尚不是自然语言或数独任务。

## 深度扩展：同一道题多算

依据 [InfiLoop §2、§4.4](https://arxiv.org/html/2610.11570v2)，固定权重与问题，增加共享块的执行次数。分别报告增加正确答案和丢失原来正确答案。准确率持平只能支持保持，不能称多算带来提升；每条曲线固定步数、固定样本，不逐题按真值挑停止点。

- 全部 11 池、43,000 查询：逐轮 R1–256；主比较 R8→R256。
- 每池固定、与模型结果无关的最多 1,024 条：逐轮 R1–1024。
- 每池固定、嵌套的最多 256 条：逐轮 R1–16,384；主比较 R8→R16,384。原子池、A/B 两/三/四跳及训练池都保留。少量样本的深度压力测试与全池结果分别报告。
- 旧 recipe-additive、ema、content、invariant 使用参数 EMA；invariant 另测原始权重全池 R1–256。新训练终点先做原 R1–32 全池重载，再做上述 EMA 深度测试。
- 保存每轮答案 token、第一次答对、答对后是否再次出错、R8 正确样本的丢失率、R8 错误样本的纠正率、预测改变率。每轮状态常量内存递推，不缓存全部隐藏状态或词表 logits。
- 原流程完整答案+生成 EOS 在 R4/8/16/32 报告；新深度测试的主指标为全词表答案准确率，不把 teacher-forced EOS 冒称生成 EOS。扩展轮次下另报告 EOS/非实体输出率。
- 5–8 跳和位置平移复用既有结果，作为问题长度外推的另一轴；不与固定问题上的深度扩展混为一谈。

## 稳定性与结果解释

主指标：150 万步参数 EMA、R8 的图 B 两/三/四跳准确率及配对差；报告每次运行、三初始化均值/标准差/最差值。训练中记录全部预定节点，报告末五节点均值、峰值到终点回落和相邻节点最大回落；峰值仅作诊断，不代替终点。raw/EMA 分开报告。每个新数据条件单独报告原子掌握、A 留出组合和 B 组合，不将查询数当作独立世界数来制造置信度。

若原子学习下降，则描述为整体学习对数据敏感；原子学会而组合下降，则进一步支持组合过程对该分布敏感。若多算只保持旧答案，写“深度稳定”；若同一批问题更多得到正确答案，才写“深度扩展有效”。不能由少量初始化或两类合成数据宣布普遍稳定。

## 历史去重与执行

旧 native 四臂、position 三臂已结束；本批复用检查点和预测，不继续旧训练。旧单图 invariant 的终点优于 ema、过程中仍起伏，是本批动机，不是新确认结果。旧 R1–32 保存预测先作探索性再分析；本协议在新世界及新训练结果出现前冻结。

旧固定镜像在当前主机缺失。当前选择本地 LM 镜像 `sha256:27b3ab677fb92aaf4e4cd953e3a87e953c4b164a0d4d4c4785dc9779851c11d2`，已核对 PyTorch 2.8.0+cu128 / Transformers 4.57.3 与旧配方一致；仍需骨干初值哈希与旧终点 R4/R8 全池逐 token 重放通过，不能仅凭版本号声称环境完全相同。

新源码、配置、数据和依赖清单冻结到持久批次目录。独立 LM 容器仅使用实际空闲卡，保留全部失败，不抢占现有任务。GPU4 的 10-05 容器是从未进入进程的单次健康检查（Pid0、创建阶段失败），不是训练；保留容器，短测已确认 CUDA 矩阵计算、反向、同步通过。调度仅忽略这一确切失败健康检查，任何活进程仍阻止使用。训练启动时同步记录到 W&B `zsqzz/llm-memory-editability`。科学训练、独立重载、云端核验分别标记。

当前空卡显存约 96 GB，单臂限制为 16%；同一张卡至多同时运行本批两个独立容器（CPU 分开），总并行最多四条，优先使用独立空卡。任何外部 CUDA 进程或有效预约均阻止接入；不能借已有本批任务去忽略外部占用。共享资源时记录耗时但不作独占 GPU 效率比较。旧 invariant 全池 R4/R8 重放未通过之前，所有正式训练等待；工程短训可以先执行。
