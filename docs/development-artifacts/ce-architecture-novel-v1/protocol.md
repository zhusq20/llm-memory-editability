# 普通Loop、Transformer与DiscoLoop的新增事实MLP编辑对照

用户于2026-10-16授权补齐普通Loop和普通Transformer，并要求尽量并行完成，再比较新增事实回答、组合使用与旧知识保持。本批复用两个已经独立审计的原生300k基础终点，DiscoLoop复用已完成的整个MLP CE编辑；不加载TTCD适配、不重训基础、不重做DiscoLoop。

## 研究问题和历史去重

已有`ce-scope-discoloop-novel-v1`只比较同一个DiscoLoop的参数范围，不能建立架构优势。早期小模型原子CE改变了图、模型、更新任务与保护目标，不能代替本批。新增比较仅改变原生基础架构：四层循环两轮普通Loop、八个独立层普通Transformer；已有DiscoLoop为四层两轮并保留软解码再编码通道。全部保留完整残差、因果attention、归一化和MLP。来源与方法沿用[原CE协议](../ce-scope-discoloop-novel-v1/protocol.md)及其实际编辑实现；原冻结科学文件不修改。

## 固定方法、数据与预算

- 同一Wang图、初始化种子、训练数据流和300k普通监督预算；层独立随机初始化，普通Transformer不复制Loop层。
- 同8条开发、32条正式原图缺失键及其256条新→旧、253条旧→新问题；每次独立从基础出发，不累计32条编辑。
- 只改所有物理MLP的up/down weight和bias，冻结LayerNorm、attention、embedding。循环架构两轮使用同一份改动。普通Transformer有8份MLP，故可编辑参数及计算不同，分别报告。
- 每事实20次Adam更新，新原子尾实体CE、10倍旧输出KL、逐元素原值±0.0005限制、梯度裁剪1；其余优化与原CE协议相同。不监督新EOS或新增两跳答案。
- 复用原4096旧原子/4096旧训练组合保护池、相同20批16+16样本、相同开发/正式七池。各模型用自己的编辑前输出产生KL教师，不使用DiscoLoop作为教师。
- 每架构同四档学习率5e-6/2e-5/8e-5/3.2e-4。仅按8条开发原子及旧池保持选择；最差池原正确保持99.5%为原门槛，沿用原排序和未达门槛的处理。开发不读取新增两跳结果。若某旧池写前正确数为0，其保持率为NA并排除最小保持率计算，完整报告该零覆盖；不增加旧题或将NA当成100%。这一处理仅扩展原实现未覆盖的零分母情况，其余排序规则不变。
- 每新架构开发640、正式640，共2560科学编辑更新；全尺寸工程预检每架构2步，精确恢复后不留更新。基础/外层训练0，独立审计优化0。

## 评分与判读

使用原greedy实体答案与EOS联合评分、同一原始问题及模型自行分步参照。先报全32事实及全部两跳，再报新原子已写成、必要旧事实原正确且保持等条件子集和覆盖；另报三个架构共同满足这些前提的同题子集。旧保持按各模型原正确题计算，同时保留写前/写后全池读数。七池各128题在32状态重复，不当作独立知识。

普通Transformer没有轮间边界，因此本批共同主比较只使用最终原生输出，不给它虚构第一轮或DiscoLoop通道。DiscoLoop既有逐轮观察保留，共同比较直接从其已审计原始预测按同一终点评分重新汇总，不重新编辑。

按32个事实聚类的配对bootstrap，沿用原10000次及随机种子。原生基础的完整七池能力、总/可编辑参数、编辑及保护曝光、token、矩阵计算代理、显存与时间分别报告。基础组合能力不同是架构整体比较的实际差异；本批不能唯一识别写入传播机制，也不能声称等计算成本或累计持续学习优势。只有一张已观察图、每架构一个初始化。

## 执行、资源和审计

固定LM镜像和`docker --context lm-memory`，两架构独立容器、CPU80–83/84–87、各32GiB内存、独立私有输出卷；资源许可时并行。优先申请实际上空闲的GPU并加锁；若没有整卡空闲，允许仅与配置中绑定完整容器ID的三条本项目merge审计共享GPU7，启动前要求至少48GiB空闲并拒绝任何非登记CUDA PID。两新增臂各分配20%显存上限，CPU与原审计分离。不得抢占外部进程，阶段间重新核查资源；没有合格资源时等待，不扩展跨用户共享。私有主机目录权限及旧实验不修改。持久材料位于`/ossfs/workspace/llm-memory-editability/ce-architecture-novel-v1/`，私有卷经Docker API复制归档；最低临时空余12GiB。

先运行固定镜像契约及Ruff，再完成每架构全尺寸前向/反向、参数冻结、保存重载、基础精确恢复预检。开发、正式编辑和独立新容器重放逐阶段执行；两臂相互独立。完整64个保存MLP状态逐字段重放所有原始读出，检查原模型与输入哈希。正式编辑不因评分失败重做；工程失败保留并另记修订。

每阶段在线W&B，团队`zhusq20`、项目`llm-memory-editability`，启动即记录；云端完成状态、更新计数及下载的完整结果JSON哈希核验通过后才发布三架构比较。恢复先读controller-process/state、冻结配置、各阶段退出码和实际LM容器，不重复提交。未通过的阶段不得称为完成。
