# 更新门：训练时长与门学习率的分开比较

2026-10-17 UTC，用户明确授权按讨论的计划开展实验。本轮在已经观察的开发世界上，把三个完成的 300k 模型继续训练，并从同一个学习门检查点分出降低门学习率的一支。它是一次事后提出、事先固定执行矩阵的开发比较；不称独立世界确认。

## 问题、历史与边界

先前 300k 的结果不能当作最终能力上限。当前 P 的图 B 三跳从 256k 的 10.30% 升至 300k 的 37.20%；学习门 .90 在图 A 未见四跳达到 98.18%，而图 B 三跳只有 15.40%。更早的 `grokking-reproduction-v1` 有 1.5M 长训和延迟泛化，但其图规模、训练集和模型均不同，不能直接把其步数解释为本任务的收敛时刻。

本轮准备时，远端 .95 批次完成：学习门/固定门的图 B 三跳为 78.18/39.64%，图 A 四跳为 97.02/1.10%。这反驳“现有数据完全不能显示门的优势”的笼统说法，但不能把 .90/.95 的跨主机差异全部归因于门初值。该结果不触发新网格；本批固定续训 .90，以回答已观察的较弱表现是否受时长和后期门学习率影响。

本轮不同于 [原 300k 比较](../paper-update-gate-multihop-v1/protocol.md)：复用原训练全部状态，改变的是剩余训练预算，以及其中一支从 300001 步起的更新门学习率。不是重复启动已完成训练，也不是重置 Adam 的长训。原高学习率 Loop/DiscoLoop 网格改变全模型学习率；它没有检验这次新增门的单独学习率。本批不扩展旧 KV、额外损失、图、种子、门初值或权重衰减网格。

## 固定矩阵

配置为 [paper-update-gate-continuation-v1.json](../../../configs/paper-update-gate-continuation-v1.json)。四臂均从绝对步数 300000 到 1500000，每臂新增 1200000 步，总计 **4800000 次新科学更新**；共享的三个唯一父检查点已含 900000 次历史更新，不重复计入本轮新增成本。

| 臂 | 300k 父检查点 | 主干及原注入门 LR | 新增更新门 LR |
| --- | --- | --- | --- |
| `paper` | 已完成 P，u=1 | 1e-4 | 无新增学习门 |
| `fixed-update` | 已完成固定 u=.90 | 1e-4 | 固定 buffer |
| `token-update` | 已完成学习 u，初值 .90 | 1e-4 | 1e-4 |
| `token-update-half-lr` | 与上一臂完全相同的 300k 文件 | 1e-4 | 5e-5 |

所有臂保留同一世界、训练数据、最终答案/EOS 损失、batch512、原 warmup2000、AdamW beta=(.9,.999)、eps=1e-8、wd=.1、全局梯度裁剪1、BF16 AMP、TF32、原轮数4和完整 GPT 模块。学习率在原 warmup 后为常数，续训**不再 warmup**。保留末轮直接读 H、原 P 的词表再编码及注入门；只有非末轮执行 `X+u(H-X)+g_P q`。

新门的 `gate_update_weight` 和 `gate_update_bias` 独立为零衰减组；原注入门仍用原学习率和零衰减。两条学习门分支都采用相同的三组优化器布局，其中一支门 LR 系数为1，另一支为.5。恢复时先按原两组布局载入完整 Adam 状态，再按参数对象移出两个新门参数，避免按序号错误对应动量。其他两个模型仍保留原两组。

“残差越多，学习率必须越小”不是本轮的数学前提。这里的 u 乘完整块的净更新 H−X；在匹配前向的局部线性、平方损失模型中，新增可训练参数可增加输出核的半正定项，但这不是实际 AdamW 的稳定学习率公式。门 LR 减半是受控检验，不声称从残差数量推算出了最优 LR。它从 300k 之后才生效，不能检验从初始化就采用较小 LR，也不能排除早期训练形成的难以逆转的差异。

## 恢复与检查

源文件使用三个父目录的 `latest.pt`，而非仅包含权重的 `checkpoint-0300000.pt`。完整恢复模型、Adam 一阶/二阶动量及每参数步数、采样器 RNG/本 epoch 剩余样本、逐样本累计曝光、CPU/CUDA RNG、训练计时。父文件、原配置、数据和源代码摘要记录在配置及冻结清单；父产物保持只读。

CUDA Graph 的准备包含会被撤销的更新。新入口对每臂实际检查准备前后模型、全部 Adam 状态与 CPU/CUDA RNG 完全一致，才进入科学训练。每个 100k 节点写权重、完整恢复状态、全量预测和曝光计数。`latest.pt` 原子替换，不修改此前权重节点。新批三组状态的未来恢复须按其保存的参数组名另设恢复入口；本控制器不会自行重启失败任务。

保留此前明确免除工程短训和独立终点审计的偏好；本轮不追加32步短训/完整面板重放。针对新增恢复代码，做真实父检查点的连续更新与恢复更新一致性验证：10次废弃有效更新、28次随后撤销的图准备更新，均不进入任何科学训练。三个模型的全部参数/Adam/样本/RNG/损失逐值一致；半 LR 当步只有新门更新改变，Adam 动量和其余参数仍逐值一致。门权重/偏置位移范数比约 .499999/.502283，微小偏差来自 FP32 参数差分舍入。CPU 检查还覆盖 epoch 尾部掩码批次、曝光与错误配置拒绝。

## 评测和解释

主指标为**绝对1500000步、推理R4、图B三跳全词表答案准确率**。预定比较是半 LR 减原 LR（同一父状态），学习门减固定门，以及各条件减 P。300k 起点复用并明确标记原测量；400k、500k、……、1500k 均保留完整11池，共43k查询，记录答案、生成 EOS、NLL、前提覆盖及已有条件子集；终点另用同一个检查点做R1–4网格。评分函数和面板不变，不取最好检查点或最好推理轮数代替主指标，不依据中途分数早停。

图 A/B 在各跳数的评测关系模板没有交集，因此跨图差距同时包含模板差异。相同面板上不同训练臂的比较仍可做，但不能把 A/B 差距只归因于图迁移。保留两图原子表现，以免把原子事实未掌握解释为组合瓶颈。查询、模板、检查点及推理轮数均不是独立世界，不据它们给出跨世界显著性结论。

若差距随共同长训缩小，支持300k排序依赖预算；若半 LR 分支在同一预算下更好，支持后期单独控制门步长在此起点有帮助。均不足以建立唯一机制、普遍最优 LR 或跨图确认。如果1500k仍在变化，继续明确未观测到收敛，不自动再延长。本轮分别记录绝对/新增步数、真实曝光、有效/执行 token、总参数、矩阵 FLOPs、继承/新增训练时间和容器时间；门的逐点操作不包含在矩阵 FLOPs中。

## 执行与监控

固定镜像 `sha256:27b3ab677fb92aaf4e4cd953e3a87e953c4b164a0d4d4c4785dc9779851c11d2`，与 .90 父批一致。P 的历史300k来自另一镜像，本批四臂使用同一新环境；上述数值检查证明当前环境恢复实现正确，不证明P历史轨迹跨环境逐值等价。

显式使用 `docker --context lm-memory`。按实际空闲资源使用两卡：GPU1依次 `token-update → paper`，GPU2依次 `token-update-half-lr → fixed-update`；每臂训练完成后做终点网格，再释放给下一臂。每阶段启动前核对 CUDA 进程和两个 Docker context 的 GPU 预约，不抢占。各容器2 CPU、16GiB内存、2GiB shm；每15秒记录进程和资源，每60秒持久镜像输出，所有失败和退出码保留。每阶段硬超时24小时，控制器不因指标平台期终止，也不自动重试失败臂。

本地主机执行目录 `/tmp/paper-update-gate-continuation-v1-execution`；源输入另存持久批目录的 `inputs/`，输出镜像到持久批目录的 `execution/`。仓库入口 `results/paper-update-gate-continuation-v1/execution` 指向该持久输出，原模型和数据来源不改。恢复先读 `controller-process.json`、`controller-state.json`、冻结清单及实际容器状态，不重复运行提交命令。

W&B 团队 `zhusq20`，项目 `llm-memory-editability`，新组名 `paper-update-gate-continuation-v1`，与训练同步在线记录，凭据仅由私有文件注入容器。训练/网格完成、在线记录、独立重载审计和云端终点核验是不同状态；本轮后两项未请求，不记为通过。后续真实状态由 [roadmap](../../roadmap.md#paper-update-gate-continuation-v1) 和 [结果](../../results.md#paper-update-gate-continuation-v1) 维护。
