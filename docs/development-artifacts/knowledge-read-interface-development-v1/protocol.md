# 知识调用接口：已知实体新增事实的标定、注入与移植（开发）

## 状态与问题

2026-10-19，用户提出主线并确定范围：先做**已知实体的新增事实**，全新实体与改写旧事实放第二步；主模型为Qwen3-1.7B与Qwen3.5-2B。本协议是阶段0–2的设计，**尚未获执行授权**；阶段3（算法）另行授权。路线见[roadmap §4](../../roadmap.md#read-interface)。

**主要问题：** 注入的新事实能被答出却用不起来，原因是哪一种？

- **A 读取器缺失：** 调用功能需要为新知识重新学习。
- **B 地址错位：** 通用调用功能已存在，注入写到了它不读的位置或格式。
- **C 调用次序：** 单遍前向只调用一次读取器，第一跳结果来不及被再次调用。

三者对应不同的算法：A需要读取适配器，B需要改写入位置或加转接，C需要重复调用读取器。本批只做诊断，不比较算法。

## 模型与环境

| 模型 | 结构 | 说明 |
|---|---|---|
| `Qwen/Qwen3-1.7B` | 28层标准Transformer，全部softmax attention | 发布的后训练权重 |
| `Qwen/Qwen3.5-2B` | 24层；每3层Gated DeltaNet后接1层全注意力（第3/7/11/15/19/23层，0起）；每层都有SwiGLU MLP（中间维6144） | 视觉语言封装，只用文本路径 |

- **两种回答模式：** 直接回答与CoT都关闭thinking；CoT为显式分步回答，以“Final answer:”结尾（原设计为开启thinking，见下文“实际执行”中的修改原因）。均为贪心解码，revision在下载时固定并记录。
- **镜像：** 在固定LM镜像`sha256:27b3ab67…`上只升级`transformers==5.20.2`（随之升级huggingface_hub≥1.31、tokenizers≥0.23.1、typer）。已在一次性容器中核验：`qwen3_5`可导入，两个模型的config可加载，torch 2.8.0+cu128不变，pip无依赖冲突。
- **DeltaNet内核：** 未安装快速内核，使用torch实现，实测耗时另报。
- **执行方式：** 按用户偏好快速启动，只做CPU契约测试与ruff，仓库只读挂载，输出写入持久工作区后复制进`results/`。W&B记录到`zsqzz/llm-memory-editability`。

## 数据：已知实体的新增事实

**主语与取值。** 主语与取值都是各国首都，由阶段0按模型分别筛选。

- 主语h必须满足：“C的首都是哪座城市？”→h，且“h是哪个国家的首都？”→C，两问都答对。
- 取值v必须满足：它所在的国家能答对。
- 每个h只加一条新事实；每个v至多使用一次；h与v不同国。用固定种子分配。

**新关系。** 四个虚构的单值关系，例如“Aurora交流伙伴城市”。名称是新造的，不对应任何真实关系，因此是新增而非改写。写入前模型对正确取值的概率应接近候选间均匀；先验另报，先验异常的事实保留并单列。

**所有事实在看结果前随机对半分为`F_adapt`与`F_test`**，留给阶段3的读取适配器使用；本批对两半同等处理。

| 用途 | 内容 | 例子 |
|---|---|---|
| U0 训练形式回忆 | 训练时的问句 | — |
| U1 换问法 | 4个留出模板，换措辞、语序，含填空式 | — |
| U2 新事实作第一跳（新→旧） | 2个模板；直接回答（U2）与CoT（U2c） | “Tokyo的Aurora交流伙伴城市位于哪个国家？”→country(v) |
| U3 新事实作第二跳（旧→新） | 2个模板；直接回答（U3）与CoT（U3c） | “日本首都的Aurora交流伙伴城市是哪座？”→v |
| U4 上下文上限 | 原模型，事实放在系统提示中，测U1–U3 | — |
| 捷径对照 | 去掉第一跳关系，“日本的Aurora交流伙伴城市是？”（Biran等的筛选方式）；先验对照 | — |

**计分。** 按实体名与别名表字符串匹配。严格：回答中第一个出现的实体就是正确答案。宽松：回答中包含正确答案。完整生成全部保留。

## 阶段0：标定（零训练）

**0a 前提筛选。** 每个模型分别进行：

- h、C、v及其国家的自然事实都已掌握；
- U2/U3在上下文中能答对（上限）。

前提不满足的事实保留并单列，覆盖率另报。

**0b 读取器的自然能力参照。** 用自然两跳题检验读取器在自然知识上能否完成同类组合。采用Biran等的筛选：两条单跳都正确，并排除去掉第一跳实体或第一跳关系后仍能答对的题。

- **预定规则：** 某个模型在某种用途上的自然参照低于10%时，该用途的直接回答不参与A/B/C归类，只报告。

**0c 读取接口。** 用自然事实做实体替换修补：把源提示（实体e′）在第l层主体token的残差，替换进目标提示（实体e，同一模板），测输出是否改为e′的属性。

- 用途包括：h的国家（2个模板）；h作主语的自然两跳，例如“首都为h的国家使用什么货币”。
- 按层扫描，主体末token与全部主体token两种修补都做；排除BOS。
- **预定的接口层段L*：** 对每种用途，替换成功率都≥该用途最大值80%的层。

**0d 读取器定位。**

- **Qwen3-1.7B：** 用Geva等的attention knockout，在k=5层窗口内阻断最后位置对主体位置的注意力，测自然用途下降。
- **Qwen3.5-2B，全注意力层：** 同上。
- **Qwen3.5-2B，DeltaNet层：** 定义为阻断该层token mixer中从主体位置流向之后位置的信息。之后位置的mixer输出取自另一次前向：在那次前向中，主体位置的mixer输入换成参考集均值（参照Sharma等2024在Mamba上的做法）。主体位置自身的输出保持不变。窗口为4层。

DeltaNet层的knockout没有先例，与attention knockout不是同一操作，两类层分开报告。

**0e 桥实体形成时间（描述性）。** 在自然两跳上，用Patchscopes的实体描述目标提示，解码第一跳末位置与最后位置在各层的桥实体，供阶段2比较。

## 阶段1：注入（新增训练）

每个模型、每种方法都从原模型出发，**同一批事实一次全部注入**，单种子。

| 方法 | 数据与目标 | 可训练参数 |
|---|---|---|
| M1 陈述SFT | 每条事实2种固定格式（陈述＋问答），参照O'Neill的重复条件；损失只算答案token | 全参数 |
| M2 多样数据SFT | 每条事实24条：改写陈述、多模板问答、单跳情景用法；不含任何两跳题和评测模板 | 全参数 |
| M3 上下文蒸馏 | teacher为原模型＋系统提示中的事实，在M2的24个提示上贪心作答；学生沿该回答拟合teacher全词表分布（前向KL） | 全参数 |
| M4 MEMIT | 写在主体末token、早中层MLP；协方差用100k条Wikitext样本 | 编辑层的down投影 |
| M5 仅down投影SFT | M1的数据 | 所有层的`mlp.down_proj` |

**校准与停止规则：**

- **校准事实：** 用10条额外的校准事实选择超参，它们不进入主集合。
- **SFT类学习率：** 从{1e-5, 3e-5}中选（M5为{3e-5, 1e-4}）。按Hase等的结论，MEMIT的层段与λ通过写入效果扫描选择（候选三个早中层窗口×λ∈{5k, 15k}），不按定位峰值选。所有校准只看U0写入与保持，不看任何两跳结果。
- **步数：** M1–M3、M5匹配优化步数。
- **停止：** U0严格正确率≥95%，或达到30个epoch。
- **成本记录：** token、步数、可训练参数、FLOPs估算与耗时分别记录。

**写入判据：** U0严格正确率≥90%才视为“已写入”；未达标的方法保留全部结果并标注。后续归类只用已写入且前提通过的事实。

## 阶段2：接口移植（零训练）

记M为原模型，M′为某方法注入后的模型。

| 移植 | 做法 | 回答的问题 |
|---|---|---|
| T1 正向（M′→M） | M′在同一提示下主体h各token的残差，从源层l_src修补到M的目标层l_tgt，再继续生成。用于U0、U1、U2、U2c | 原读取器能否用上M′接口上的新知识 |
| T2 反向（M→M′） | 把M的主体表示修补进M′ | M′的新知识是否只经接口传递；若反向修补后仍能答出，说明新知识存在别处（如答案位置的捷径） |
| T3 桥位置（用于U3） | 在U3提示中，h不出现，无法在主体位置修补。CoT（U3c）下，在模型生成的h的token上做T1；直接回答（U3）下，把M′在显式h提示中的表示修补到M′的第一跳末位置（参照Dai等的跨情境对照） | 读取器能否在桥实体表示与显式token一致时用上新事实 |
| T4 回补（用于U2失败题） | Biran等的back-patching：把后层状态修补回较早层 | 失败是否来自调用太晚 |

**层对的选择：**

- Dai与Biran都发现，有效修补往往是“较后的源层→较早或中间的目标层”，因此按每2层的网格扫描l_src≥l_tgt。
- **主层对在校准事实上预先固定：** L*内的同层修补，以及校准事实上最好的“后→前”层对。
- 全网格中“任一层对答对即算成功”的上界只作描述，不作主指标。

**预定归类规则（每个“方法×用途”，在已写入且前提通过的事实上）：**

| 归类 | 条件 |
|---|---|
| B 地址错位 | 主层对T1使M答出新事实的比例＜M′自身U0比例的50%，而T2后M′仍保留≥50% |
| 接口承载 | 主层对T1使M答出新事实的比例≥M′自身U0比例的50% |
| A 读取器缺失 | 接口承载；该用途的自然参照≥10%；但该用途在M′中、以及经T1/T3移植后的M中，都低于上下文上限的50% |
| C 调用次序 | 接口承载；CoT版本的正确率≥两条单跳都正确比例的80%；直接回答失败；固定层对的T4或T3恢复≥该用途失败题的25% |
| 未归类 | 其它情形如实报告 |

**规则的地位：** 阈值是开发规则，不当作显著性门槛。同时报告连续量：各层对的恢复率、新答案与旧答案概率，以及沿用O'Neill做法的标准陈述log-prob提升。
