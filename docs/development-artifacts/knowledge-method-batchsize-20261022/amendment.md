# Knowledge：从现有进度增大 batch（2026-10-22）

用户明确要求不从基础模型重训，而从当前训练进度继续，尽量增大物理batch以提升吞吐。本修订覆盖八组已有任务；原模型、数据、参数范围、损失、精度和评价保留。原batch4、每组372300次更新是切换前协议；新的终点为每组累计1489200次样本曝光，即同一297840行数据的五个完整epoch，优化器更新总数随实际batch和切换位置变化。

接管原调度器后，六条旧训练继续运行，逐条等待比接管时更新的原子提交检查点；只停止相应旧容器，保留其权重、日志与身份记录。新容器验证数据和原配置，逐张量核对训练参数、Adam动量和计数器。工程试跑使用当前权重，但试跑结束后重新打开原检查点，再恢复参数、优化器、RNG；试跑更新不进入科学结果。两条尚未开始的down-LoRA仍是原队列任务，从原基础初始化开始，不能声称它们已有可接续进度。

样本序列沿用原seed加epoch的确定性排列，以检查点exposure恢复行位置，批尾不跨epoch、不丢尾批。学习率沿用原函数，以exposure/4作为原进度坐标，不按batch倍数放大学习率。Adam自身的更新计数接续原值，后续每次实际更新只加一。变大batch会改变优化过程；各组可能选择不同batch，后续结果必须带上切换点与batch记录，不再描述为全程统一batch4的比较。

每个GPU沿用原两个任务。逐个测试4/8/16/32/64/128，先用最长实际段落加512题目和512答案的两次完整更新检查显存，再在同一256条训练样本上测吞吐；不使用评价集选batch。显存不足时由受限PyTorch分配器拒绝，不挤占同卡任务；保留失败测量。候选中选择吞吐距最佳不超过2%的最大batch。保留每任务6GiB、整卡8GiB余量；新进程与其他项目预约都会阻止入场。共享GPU短测不作为独占速度或整批加速倍数结论。

为减少共享存储停顿，所有接续任务使用独立CPU快照、每任务32MiB/s后台保存。保存触发间隔改为60000样本或1800秒，以先到者为准；保持最多一个待写快照、原子替换和失败传播。进度/W&B每2000样本及首步、终点记录。保留原W&B run ID，在新字段记录batch修订，日志步采用单调偏移；真实optimizer_updates与exposure单列。

原异步保存可能在检查点快照之后继续更新。切换记录保存旧进度与实际载入步数，差额列为重算计算；旧进度每100步记录，另报最多99次尚未报告的更新，不能声称绝对零回退。旧检查点不覆盖，新检查点放在本修订runs目录。训练完成后仍使用原独立重载和原评价入口，评价阶段等待独占原资源池内的一张空闲卡。

固定镜像CPU验证12项通过，包括不同batch下精确接续样本序列、epoch边界、学习率连续、Adam状态恢复、原异步快照和调度保护；Ruff检查与格式通过。初次检查用户ID错误、只读缓存错误和格式问题保留原日志。实际CUDA恢复、batch峰值、吞吐与是否已开始接续分别见[持久修订](../../../results/knowledge-method-batchsize-20261022/runtime/amendment.json)、各组`restore-before-probe.json`、`benchmark.json`、`selection.json`和`progress.json`，不把CPU验证写成CUDA已通过。

本修订未增加数据曝光预算，不增加科学任务；工程试跑和检查点后的重算另计。GPU池仍为sn4622128200的3/6/8。恢复先读[交接](../../../results/knowledge-method-batchsize-20261022/RUNNING.txt)、持久区最新controller与实际LM Docker；不重启已退役控制器或失败入口。
