# 全参数立即启动修订

用户在 2026-10-24（芝加哥）明确回复：**“立即开始，固定全参数”**。
这替代本批“等待八组完整分析后选择范围”的启动条件，以及暂定 down-only 范围。

- 开发、正式新增、原子改写和真实文档应用的 PD／SFT 全部采用 Qwen3-1.7B 全参数更新；教师仍为独立冻结底座。
- 原八组仍只有七组终点齐全。其报告、云端快照和最新采集状态在启动决策中另存带哈希的快照，不能声称八组已完成或由八组完整排名选出 full。
- PD-LoRA 保留原容器、参数、Adam、RNG、进度和 GPU3；只替换调度控制器，将其资源范围缩为 GPU3，完成原训练、重载、评测与云端收尾。采集器继续工作。
- 新批次只使用 GPU4／6／8，每卡一个独占阶段。旧等待控制器退役，保存原状态、源码和 down-only 配置后，由全参数冻结源码接手同一批次；全部阶段原本尚未提交。
- 三卡首先并行生成开发回答、正式回答和真实文档开发校准问题。生成只读取训练材料；提前生成不允许正式评测参与开发预算选择。正式显存核验和训练仍在开发预算选定之后，真实文档正式阶段仍在改写比较与语义审核之后。
- 数据、模型 revision、采样、优化设置、监督／回放 token 预算、评价和失败保留规则不变。开发事实 32 对、正式 128 对、应用 64 案例；正式主监督预算由原开发规则在 800768／1601536 token 中选择，改写为四分之一。
- 原 CPU 数据审计保留原配置哈希；本修订核对所有数据文件未变，并单列新配置哈希。新配置见 `configs/knowledge-use-coverage-full-v1.json`。
- 全参数实际 CUDA 最长输入、梯度、冻结教师、恢复与独立重载必须通过，预留每任务 6 GiB 加整卡 8 GiB；工程更新丢弃。未通过时保留失败，不冒充正式训练。

全参数并非依据临时七组结果选出的最优范围，而是用户指定的主比较范围。原结果中的收益与保持代价一起保留；不修改八组配方，也不恢复 Loop 暂缓任务。
