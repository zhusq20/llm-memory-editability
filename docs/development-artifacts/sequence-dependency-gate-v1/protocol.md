# 序列依赖任务上的跨 Loop 残差门评测

用户于2026-10-18明确确认采用具有序列逻辑依赖的任务评测学习门，并要求尽量复用已有数据。本批选用 NDR 作者的 ListOps `big` 和 simple arithmetic 构造。两任务、四架构、各100k更新是本轮选定的开发比较范围，并非用户指定的数值预算；不增加训练损失、课程或自适应停止。

## 问题与解释边界

主问题是：在表达式包含多条子计算分支、随后汇合的任务上，跨轮残差门是否改善固定训练预算的任务准确率，以及增加推理轮数后是否更能保持已得到的正确答案？这一任务比单一路径多跳查询更接近“某一分支先完成、另一分支仍未完成”的情形。任务结构提供这种机会，不要求模型采用唯一的树执行算法，也不证明门实际承担了等待或保存的角色。

例如 `[SM [MAX 2 7 ] [MIN [SM 3 5 ] 9 ] ]` 的答案为5。左侧MAX的输出为7；右侧先求3+5 mod10=8，再与9比较，得到8；最后7+8 mod10=5。所有符号仍以作者原来的线性次序出现。因果模型在表达式后的答案位置能读到完整输入；前缀运算符位置不能读取右侧输入，不能照搬原双向NDR的运算符位置解释。

本批是受控行为开发实验。一个数据实现、一个初始化不支持多种子稳健性、大语言模型收益或通用最优架构。固定100k终点的低分不证明架构极限；作者普通Universal Transformer使用200k更新，本批所有架构统一100k以控制曝光，不声称完整复现其分数。

## 来源与尽量复用

- [NDR论文](https://arxiv.org/abs/2110.07732)：ICLR 2022，方法§2、任务§3、分支执行§4及附录C。
- [作者代码](https://github.com/RobertCsordas/ndr)，MIT，固定commit `da20530dfb4336deddfbe5e79d62e72d1dc2580e`。
- 数据生成来自 `dataset/listops.py`、`dataset/simple_arithmetic.py`，实际分割来自 `tasks/simple/listops_data_mixin.py`、`tasks/simple/simple_arithmetics_data_mixin.py`；训练参考相应 `sweeps/transformer_control_flow/` 配方。

保留作者运算、表达式语法、采样函数、长度和深度条件。源文件和许可证随数据来源存档。作者ListOps的样本种子受Python字符串hash和CPU数影响，本批使用稳定的分割种子和有序生成块；最终数据逐文件哈希冻结，不声称恢复作者当年的相同随机样本。

| 数据条件 | ListOps | 算术 |
|---|---|---|
| 运算 | MIN、MAX、MED向下取整、求和mod10；2–5参数 | 全括号二元加法、乘法，mod10 |
| 训练 | 1,000,000条 | 100,000条复合题＋200条完整原子运算 |
| 训练运算深度 | 1–5 | 1–5 |
| 深度验证／测试 | 6／7–8 | 6／7–8 |
| 采样子表达式概率 | 0.3 | 训练/IID为0.2，深度验证/测试为0.3 |
| 长度 | 作者内部length≤50，另记实际token数 | 字符/token≤50 |

叶节点在作者源码中深度为1；表中的“运算深度”比源码的树深度小1。ListOps按作者`max_dependency_depth`平衡，该量只追踪最终被MIN/MAX/MED选中的结果分支，不能解释为事先可忽略其它孩子的最小必要计算深度。算术保留作者补足深度时深枝总在右侧的实现，也保留乘零等捷径。

明确的分割修订是：增加独立的IID验证与IID测试池，训练/验证/测试表达式文本显式排重，拒绝后补足原定样本量。每个留出池1000条；训练诊断池另抽1000条，明确属于训练题。算术原代码的IID池包含与训练相同的200条完整原子题，本批不把它们混入留出IID准确率。保留原子全集训练，不改变其真值。

独立解释器核对真值、语法树与分组。审计记录实际长度、答案位置、token×位置覆盖及分割交集。统计完整树深度、作者深度、至少两条非叶子分支汇合的节点数、兄弟深度差；这些字段均只用于评价，不输入模型。保留全池结果，不能事后只挑“有利的依赖题”。

## 四格模型与普通训练

设X为本轮输入、H为完整Transformer块输出，q为原DiscoLoop软解码再编码反馈。每个任务均运行下表四臂，最后一轮直接读取H：

| 名称 | 非末轮交接 |
|---|---|
| loop | H |
| only-u | X+u(H−X) |
| disco | H+q |
| fixed-q-plus-u | X+u(H−X)+q |

u为现有共享token标量门，范围0–1、初值.95；保留其完整定义。q的注入系数固定为1，反馈内容仍随状态与参数变化。两格含q、两格不含q，各自比较有无u。无学习注入g、无MLP子层门、无历史状态新结构。u=.95也改变初始残差缩放，因此本批不能单独区分学习适应和固定阻尼；没有暗中加入固定u的科学训练。

同任务四臂从相同主干初值开始，共用数据顺序、监督、优化与训练轮数。完整因果GPT块保留残差、LayerNorm、attention、MLP和可学习绝对位置；宽256、4头、MLP1024、单层共享块。ListOps训练20轮，算术15轮，参考作者相应深度预算，不假定一轮必然执行一次运算。比原NDR改变了模型与读出方式，不能引用其分数作为本批对照。

输入为原表达式加常规边界符，末端生成一个数字和EOS；普通全词表答案+EOS交叉熵。使用AdamW、batch512、2000步warmup、全局梯度裁剪，dropout .1。ListOps学习率2e-4、weight decay .05；算术1.5e-4、.01。各100k更新，总800k；保留初始化、流和dropout种子。相同种子不意味着不同架构拥有完全相同的随机算子执行轨迹。

## 评价与成本

训练节点为0、1k、5k、10k、25k、50k、75k、100k，仅测训练诊断、IID验证、深度验证。IID与深度测试只在固定100k终点读取；不按测试结果挑checkpoint或挑最优推理轮数。

主比较为训练轮数下的最终答案准确率和答案+EOS完整匹配。终点另扫ListOps R={1,4,8,12,20,24}、算术R={1,4,8,15,20}，分别报告训练时间波动与推理轮数变化。EOS在模型自己生成的答案后计算。保存逐样本预测和真值；分组同时报告覆盖率与样本数，控制长度后再讨论依赖深度差异。解释分支不平衡是数据属性，不能直接当作模型内部等待时长。

记录参数、样本曝光、有效token、填充token、矩阵FLOPs估算、训练时间与硬件。两任务词表很小，q的开销和语义空间与旧知识图任务不同；不能把跨数据集耗时差异直接归因于门。

## 执行与恢复

固定LM镜像 `sha256:27b3ab677fb92aaf4e4cd953e3a87e953c4b164a0d4d4c4785dc9779851c11d2`，每臂独立容器，显式`lm-memory`上下文。使用两个空闲GPU通道，与旧GPU0/1任务合计不超过本用户四张GPU。每阶段重新核对UUID、空闲、保留容器和用户GPU并集，不抢占。

先完成数据契约、CPU测试和每臂一次全尺寸CUDA工程更新并丢弃，核对CUDA graph恢复。沿用用户对32步短训及独立重载/云端终点审计的豁免；在线W&B学习曲线保留。工程成功不是科学收益。正式启动前冻结源码、数据、配置和许可证；任何修订留独立尝试及失败记录。

恢复先读本批`science-process.json`、`science-state.json`、各任务`runs/<arm>/status.json`及实际Docker状态。旧多跳数据两臂和本批八臂是不同问题，不能相互替代或重复提交。当前执行状态另见roadmap及本批结果目录。
