# 原子知识提取随执行轮次变化：探索性补充分析

登记时间：2026-09-29T23:56:06.752587-05:00（America/Chicago）；UTC 2026-09-30T04:56:06.752587+00:00。登记时已完成正式模型循环扫描 **1 条**，清单与哈希见 [登记快照](atomic-timing-registration.json)。这项分析源于已读取的开发观察，不属于原预注册主分析，也不声称登记早于首个正式扫描；后续使用正式模型的数据仍标为 **exploratory reanalysis**。

触发观察：开发 L1 在 R=1 时，二、三、四跳模型的 ID 原子答案均为100%，OOD约18.0%/10.5%/9.0%；L2对应 ID 也均为100%，OOD约98.0%/92.2%/61.7%。这些是促成本补充的已知观察，以下固定规则不据结果筛选模型。

仅读取已有及随后完成的 L1/L2 固定检查点循环扫描原始数组，以保存世界中的 `id_atomic`/`ood_atomic` 真值划分对齐原子题，重计 R=1…8 全部答案准确率与答案+EOS准确率；并列原扫描 ID/OOD 组合的完整准确率。ID/OOD在此指事实是否参加组合训练，所有原子事实均参加过单跳训练。保留全部模型、轮次、缺失项、分母及覆盖；不追加前向或训练、不挑最佳轮次或达标阈值、不拟合预测器。

分开开发/正式模型、架构、跳数、初始化配方与检查点，先平均世界内初始化，再给各世界等权。曲线以 ID/OOD 原子颜色、答案/答案+EOS线型区分，训练轮次画竖线；记录源码与输入产物哈希。正式模型尚未齐备时公布缺失世界与初始化，不把已有子集当作完整矩阵。

本补充区分“某轮次下原子事实已可从输出提取”与“该轮次组合回答是否正确”的观察。它不能单独确定事实的内部编码位置，不能证明MLP唯一存储，也不能仅凭原子/组合差异充分解释组合失败；额外测试轮次仍是固定权重下的执行变化。

复现：`.venv/bin/python scripts/report_grok_loop_atomic_timing.py`，默认读取全部已完成开发与正式扫描，分别输出到 `atomic-timing-report/` 的 CSV、JSON 及每阶段六面板图。只验证开发可加 `--phases development --out docs/development-artifacts/grok-loop-v1/atomic-timing-development`。后续扫描齐备时重跑同一命令；未完成模型及其全部 R 仍列在 `missing.csv`，不按预测表现筛选。

开发核验：6/6 个模型、48/48 个模型×轮次、192 条分组记录齐全，原扫描总体分数全部复现。R=1 的答案准确率复现上述触发观察；同时，L1 的 ID/OOD 原子答案+EOS均为0%，L2 的 ID 原子答案+EOS为95.31%/63.54%/60.03%，OOD为96.09%/60.55%/30.86%。这些开发单世界结果只提示输出提取与完整格式成功的计算阶段可能不同。
