# 原生 bioS 属性续写：执行前冻结

本批以 2026-09-30 已授权的预训练形成过程问题为目的，只读取既有预训练权重，不训练或改写历史输出。全部样本、源码、数据与指标已在 `lock.json` 冻结后才启动 GPU。

- 两个开发世界，各从 1000 位 dev 人物中以世界加 20260930 为种子，抽取 32 位。只按原 variant-0 模板与分词边界筛选，不按模型预测筛选。合格人数为 994/995；排除 6/5 人的原因均为目标属性和后缀未形成可独立计分的原生 token 边界。
- 每人测完整出生日期与出生城市，共 128 个固定案例。六条 S/M/MP 预训练各评价 0/30/90/180/360/540 曝光权重，共 36 节点、2304 条预测。
- 日期前缀为 EOT 加原传记首句至完整日期之前；出生地前缀为 EOT 加原完整日期句，再加原第二句至出生地之前。姓名先于目标值。每个前缀与属性 token 都逐 ID 核对预存原生句子，目标未在前缀中出现。
- 两种前缀都是 S/M 已有 variant-0 的原顺序、原措辞，MP 也训练过这些句子，但具体连续句序的次数未单独复算。这测量已见文本条件下的属性记忆/续写，不测陌生问法泛化或闭卷 QA。出生地条件包含真实日期，可能以此帮助识别人，必须保留此边界。
- 只给目标属性 token 计算完整序列 NLL 与概率，不添加原语料中不存在的 EOS。贪心统一生成 9 个 token，恰等于全体最大属性 token 长度加 2；不按答案选择生成长度。分别报告完整属性 token 序列精确命中，以及再加原生后缀首 token 的精确命中。
- 同一 128 案例用于所有条件和节点；先按世界分别汇总再对两世界等权，同一人的节点不当作独立人物/世界。六条训练使用同一初始化，节点 0 不是六次独立初始化证据。
- 使用历史 GPT 实现与原 FP32 参数、BF16 autocast、TF32 设置；已核验工作区原模型/数据/训练代码与历史执行源码相同。batch=4，GPU5 进程分配上限 3 GiB，逐节点记录峰值。运行前两项关键测试核查原生前缀和无额外 EOS 的属性概率。

这轮曲线只补知识记忆/续写形成过程。与之后 QA 适配的提取表现并列时，应明确二者输入和训练阶段不同；不能把差异全部归因于单一内部接口。

复现：先 `PYTHONPATH=src .venv/bin/python scripts/run_bios_original_trajectory.py prepare`，再同脚本 `run --device cuda:5`。冻结后代码/样本变更会拒绝执行。
