# 开发后修订：排除测试事实复习次数混淆

原4000步开发的10个端点与源码保留在development，不用于确认主结论。它们单跳和训练组合大多100%，但熟悉事实留出组合仍受负载影响；低负载额外槽位重复熟悉原子，因此相关原子的总曝光并未匹配。

修正后低负载的额外槽位只重复共同子图外32个人和32个桥实体的256条anchor事实。它们不参与任何训练/测试组合；高负载额外槽位涵盖5376条额外事实，包含这些anchor。共同768条事实和组合流完全相同，两负载的测试必要原子在所有流中的总曝光严格一致。独立事实为1024/6144，词表、参数、输入形状、监督token和总步数相同。Anchor曝光次数及额外事实分布仍随负载不同，这是固定预算的负载操作，不能同时称每条事实曝光匹配。Anchor的单跳也报告。

先在同一开发世界运行五架构×两负载8000步，节点0/2000/4000/8000，另立development-matched配置及源码快照。保留原4000步结果；不拿跨修订差值推断单一机制。若末段仍持续变化，先补充开发预算敏感性，再冻结新世界确认预算。主比较、三个确认世界、架构、全池与条件评分均沿原设计；不因结果挑最佳架构或循环次数。

首次独立审计进程未开启训练使用的TF32，连续NLL存在约0.008以内差异而未通过严苛容差。统一精度设置后，原10端点的全部生成、评分、NLL与曝光均重算通过。新审计入口显式设置相同精度；不通过放宽生成或NLL标准解决。工程失败与修正保留于本记录。

## 确认前预算决定

修正后10条8000步开发及其终点重载全部完成。另固定标准2层/Loop1×2的低高负载共4条16000步开发，节点0/4000/8000/16000；单跳和训练组合100%，熟悉新链仍随预算波动，严格无组合角色池仍弱。8000步时标准2层高负载反而更高，16000步低负载更高；不择最佳节点解释统一负载定律。

在读取新世界结果前，确认统一固定16000步，0/4000/8000/16000节点；五架构、两负载、三个预定新世界、一个共同配对初始化不变，共30条。最终16000步是主端点，中间曲线和全部R均辅助，不因确认结果改变预算。这个预算增加只用于降低短训疑虑，仍不构成全局优化或架构容量上限证明；失败模型不剔除。冻结配置与源码见confirmation目录。
