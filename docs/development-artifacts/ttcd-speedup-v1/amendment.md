# TTCD同配方运行加速修订

2026-10-15，用户要求解释TTCD耗时，并在不改变实验配方的情况下加速训练和正式评测。用户此前明确取消短训；本次只做固定checkpoint的前向/梯度核验，优化器更新为0，不提交新科学训练。

## 证据与改动

GPU4现有single/stream共享一张卡，连续组每次外层更新有128事实、每事实4次内写、8事实状态依赖和贯穿先前写入的梯度。采样时single约86%、stream约93%的累计时间在计算段；日志和其他外开销只占剩余部分，不能把慢归因于存储或缺显存。无activation checkpoint重算。当前其余GPU均有任务，8/9也在本批基础训练中，不抢占任务。

1. 训练`session_write`只消费首轮capture特征，但原实现仍算未被消费的后续轮、Disco boundary和最终词表输出。新运行时对原始函数进行来源哈希约束的AST变换，仅在`capture.outer_grad=True`时首轮结束返回；原生查询、正式读取与推理写入的teacher_argmax路径保留。BF16下保留零行linear操作创建同一个共享权重cast缓存节点，保证梯度累加顺序。被省计算与传统2倍反向代理的估计同步扣除，不把旧计算成本当作新实际成本。
2. 正式评测只缓存已注册冻结骨干的完整哈希，按storage、version、shape、stride、dtype、device及参数冻结状态逐次核对身份；每个快状态仍全量哈希、保存及加载，阶段始末仍用原函数完整校验骨干。保存时一次CPU快照供快状态哈希和序列化使用，原payload/schema保持。

科学配置、初始权重、数据与排除键、事实顺序、内外层学习率、四次写入、K8梯度链、宏/微batch、loss、BF16/FP32及TF32设置、更新步数、检查点/评测节点、两套正式面板、问题/评分、独立重放和云端JSON核验全部保留。冻结源码原文件不修改；实际执行由单独冻结并登记的运行时扩展提供，不能把原源码哈希单独当作全部执行实现。新训练checkpoint及W&B配置附运行时来源，阶段另存运行时收据。

## 数值核验

训练扩展21项CPU检查通过，含普通D8、Loop、Disco × K1/K8 × FP64/FP32/BF16，快权重、损失、全部梯度和RNG逐值一致；推理与撤销路径保留。评测扩展9项CPU检查通过，三架构状态文件逐字节相同，81状态双新评测与29状态原评测及新reader审计的token/EOS/rank/score/写入历史/状态与汇总一致；参数版本变化或绕过版本的修改都会被身份/阶段完整校验捕获。

真实Disco stream1000 checkpoint、原尺寸macro512/128与micro64/32、原BF16/TF32-off的K1/K8全批前向和反向检查：所有快状态、四项损失、52份参数梯度逐值一致，慢权重不变，优化器更新0，正式题查询0。诊断在同项目GPU8现有原生训练容器内执行额外临时进程，不重启该模型；这个短时间段须从独占GPU墙钟比较中排除。单批诊断原/加速耗时约3.217/2.317秒（K1）与6.138/5.386秒（K8），仅为同卡竞争下的诊断比值，不承诺整段同幅提速。

## 运行接管与限制

现有四个训练模型进程保持原容器ID/PID，不重启、回退、重算科学步骤或修改内存中的训练实现。它们没有精确live状态的安全热切换接口；周期checkpoint落后当前步数且trace只存hexdigest，不能假称可无损即时续训。本修订先把训练加速用于尚未开始的普通/Loop TTCD阶段，把评测加速用于所有尚未开始的正式评测/重放。

仅替换三个宿主控制器：GPU4父两臂、GPU8/9架构两臂及等待中的双新补充评测。先只读预演，再只暂停旧宿主控制器，捕获原进程/模型/claim/配置/源码/截止时间，核对后结束旧宿主并取得原锁；新控制器等待原模型退出，按原阶段顺序继续，仅未来三个TTCD CLI添加只读扩展挂载和入口包装。原生基础训练/审计/云核验保持原命令。GPU4 cohort限制、GPU8/9独占申请、CPU/内存/输出隔离和原deadline保留；不因接管延长超时，不重跑prepare，不自动重试失败任务。
