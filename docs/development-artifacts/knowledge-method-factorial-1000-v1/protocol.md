# Qwen知识更新：论文评价、1000案例与八组交叉比较

2026-10-21。用户本轮要求沿用论文评价、扩大数据，并增加全参数PD、down-only PD与down-only LoRA。此协议是新批；旧32案例的权重、训练数据、EM/F1和失败记录原样保留。

**问题：同样的自然文档知识，用SFT还是Prompt Distillation写入、允许哪些参数更新，怎样影响留出多跳回答与旧能力保持？** 本轮补全两种训练配方×四种更新范围。主模型保持用户原先要求的现有Qwen3-1.7B；这是原论文方法在Qwen3上的扩展，不称原Qwen2.5数值复现。

## 依据与评价修正

[原论文](https://arxiv.org/html/2412.14964v2) §4.2、§4.7及附录O；[作者仓库](https://github.com/kallekku/prompt-distillation)固定提交`2b72919a0836f97115f0396ee753bd284c8d91d6`。

- 按用户最新要求，裁判采用 **Qwen3-4B，`enable_thinking=False`**。沿用作者HotpotQA三示例的消息内容及`extract_grade`解析，使用Qwen自己的聊天模板与终止符。输入仅问题、标准答案、候选完整回答；无文档、方法名或训练状态。温度0，最多512新token。原脚本可能回退搜索true/false的行为也保留；无效判分逐项报告。主分数为 `true数 / (true数 + false数)`，同时报告有效判分覆盖与无效数量。附录的substring match另报，EM/F1只作辅助。原论文裁判是Meta-Llama-3-8B-Instruct，因此本轮称沿用论文评价协议并替换裁判，不称评分器完全相同。
- 新Qwen闭卷生成仅给原问题，取消本项目额外的“只答短答案”指令。采用论文正文的温度0.25，最大500新token、总长6128；作者CLI默认温度0与正文不同，本轮明确选择正文值。
- 另报告原文档在场的oracle-context参照和旧问题保持。**本轮不把oracle-context叫RAG。** 论文RAG从全部1000题段落池用`text-embedding-3-small`检索top10；本轮主比较为其闭卷任务，未冒称复现完整RAG表格。
- 上一批已保存的320条闭卷/上下文生成（共同基座64条加四臂各64条）先用本轮固定Qwen3-4B裁判另行重评分，写入新批`regrade-development`。这是旧提示下的附加评分；它不能代替新批按原提示重新生成。

裁判固定官方 `Qwen/Qwen3-4B` revision `1cfa9a7208912126459214e8b04321603b3df60c`，原始非量化权重逐片核对SHA256。推理由HF Transformers/BF16执行。保留作者评分消息中的判断理由要求；这些理由是普通回答，不开启Qwen的thinking模式。所有组共用同一裁判、提示和参数。

## 数据与复用

作者CSV前1000题全部段落共 **9928段**，每段30个单跳问题，共 **297840条问答**。真实段数分布：988题10段，7题2段，另各一题5/11/8/4/6段；不填补、不替换。所有段落合在一起训练一个模型，不是每案例独立训练一个模型。

复用旧批前32题的9360条已生成问答原始记录，核对原数据、模型revision、生成温度与提示、原始记录及完成哈希。旧源数据不改，新批统一提取最后一个`</think>`之后的最终答案，未闭合或无最终答案的新增生成保留失败并重新生成；所有变更记录及原始文本均保存。旧9360条SFT答案无思考标记，PD有1条孤立结束标记及重复回答，新批仅保留其最终答案。只复用数据，八臂都从原始基础权重开始；旧四臂终点不能续训充作新批。旧数据和所有新增数据均核对不包含1000条测试问句的完全相同文本。

新增968题分三片独立生成：原CSV行号[32,355)、[355,678)、[678,1000)，分别3209、3207、3200段。三个片保留原全局case/paragraph ID；完成后验证无重叠、无遗漏、每段30题以及PD/SFT答案齐全，再合并成八臂唯一共同数据文件。所有生成只见当前段落，不见测试问题或答案；PD回复温度1.5、SFT回复0.25，问题温度1.5，batch32、最长512。截断记录保留，不教人工EOS。分片改变随机采样分组，留档，不宣称与原作者随机样本相同。

这1000题包括既有自然事实，未保证基础模型此前未知；前32题亦已用于开发。因此报告全量、原本答对/答错子集与覆盖，不把这批称为全新知识确认集。

## 八组与唯一变化

| 更新范围 | SFT：硬目标CE | PD：上下文教师分布KL | 实测可训练参数 |
| --- | --- | --- | ---: |
| 原论文模块范围LoRA（attention、MLP、lm_head） | sft_lora | pd_lora | 1,273,364,480 |
| 全参数 | sft_full | pd_full（新增） | 1,720,574,976 |
| 只更新各层down projection矩阵 | sft_down | pd_down（新增） | 352,321,536 |
| 只在各层down projection挂LoRA，原矩阵冻结 | sft_down_lora（新增） | pd_down_lora（新增） | 234,881,024 |

SFT与PD各自固定数据，跨更新范围相同；PD对SFT仍比较作者整套配方，包括不同回复采样温度，不称纯KL/CE消融。原范围LoRA与down-LoRA均r=1024、alpha=2048、dropout=.05，避免同时改变rank和模块范围；实际参数数目单列，r1024不是低成本小适配器的保证。

- **full与down的PD**：额外载入独立原始基础模型，完全冻结、eval、无梯度。教师与学生不能共享参数存储。不能以正在更新的学生充当固定教师。
- **两种LoRA PD**：所有原参数冻结，教师前向禁用adapter及dropout；学生前向恢复训练模式。
- 只有down-LoRA的adapter可训练，不能误训练原down矩阵或其它层；参数名字、梯度、冻结状态、教师输出与重载均检查。

## 训练、保持和成本

Qwen3-1.7B revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`；FP32参数、BF16 autocast。本轮一个固定seed（1234），未复现论文多seed误差条。AdamW lr1e-5、wd.1、warmup100、线性衰减、clip1，batch4、5epochs。每臂372300次优化调用、1489200次样本曝光；八臂 **2978400次更新**。温度2的前向KL无T²乘子，按每例答案token平均再batch平均；SFT按batch有效token平均。每5000步保存恢复点，终点存独立可重载权重。

数据生成、学生输入、上下文教师输入和测试均使用`enable_thinking=False`。Qwen模板在assistant前缀放置空`<think>\n\n</think>\n\n`，这一前缀不参加CE/KL损失；只监督最终答案及未截断回答的EOS。关闭显式思考文本不等于排除模型内部推理。

大数据每epoch仅构造一次相同seed的数据顺序，每小批次编码，避免每步对全数据重排和预展开全部token。CPU中断恢复契约须逐值一致；这些执行优化不改目标或曝光。输入超过8192直接报错，不静默裁剪或丢样本。

保留旧317条自然问题，按原别名规则报告原正确题保持及总准确率，二者分开。每案例固定首条训练问答作teacher-forced拟合辅助，不称事实掌握率。自然多跳主结果、原本已知/未知子集、旧保持、训练参数/有效token/耗时/显存分别报告。

依据32案例实测线性外推，新准备约88 GPU小时；新增四臂速度尚须实测，三卡完成全部矩阵规划约6–8天，非保证。八臂总步数相同不等于计算相同，PD须计教师前向，独立教师须计额外显存。

## 执行与恢复

仅在`sn4622128200`的实际空闲GPU3/6/8上动态排队，每卡一个独立容器、10 CPU、128GiB。GPU4仍有其它项目created预留，不动；其它运行任务不抢占。旧LM固定镜像和隔离PEFT/Accelerate依赖复用，源码及旧数据只读。Qwen3-4B裁判公开权重只下载一次到新批专属目录。

先做全尺寸八臂短测、新增dense PD显存与冻结教师检查、独立重载、真实judge评分检查。重载核对答案位置前1024词表logits逐值一致、全部输入位置greedy token一致及权重哈希；冻结教师核对全部答案位置全词表logits逐值一致，二者检查范围不同。通过后一次提交：旧生成重评和三个数据片并行→校验合并→八臂train→audit→paper-evaluate。等待入口以单独readiness锁和状态记录承接后台工程验证；缺结果继续等待，显式失败、源码哈希变化或24小时超时均停止，只有全部工程证据通过才调用正式入口。它不预占GPU，正式入口仍按实际资源和共享锁调度。独立teacher在训练后退出；Qwen评价完先释放，再加载judge。所有原始回答、judge理由、判分与无效输出保存。

新批`knowledge-method-factorial-1000-v1`，W&B团队`zsqzz`、项目`llm-memory-editability`。失败保留，不自动重试；先读controller、execution、stage-status及实际LM容器，再决定恢复，不重复提交。执行状态在results登记，本协议不预填通过或科学结果。
