# 连续更新与再编码共同门控：150万步配对实验

## Material Passport

- Type: controlled architecture experiment; ARS experiment-agent/run, executed inline.
- Batch: `joint-update-gate-multihop-v1`.
- Authorization: 用户选择沿用当前任务配对比较，指定GPU5，随后将预算改为150万步，要求本机构建Docker；明确确认GPU5/6利用率显示异常可以直接启动。
- Verification: 工程检查与科学终点分别记录；训练尚未完成时不产生性能排序结论。

## 问题与唯一变化

比较同一学习门是否也应该控制本轮新产生的再编码。旧学习门为
`X + u(H)(H-X) + g(H)q(H)`，本次为
`X + u(H)(H + g(H)q(H) - X)`。
X是完整的本轮输入，包含上一轮实际注入；H是完整Transformer块输出。
只改变前三次轮间交接，第四轮始终直接读取H。不是恢复旧Q-Full的末轮反馈。

u为无仿射LN(H)上的标量sigmoid，跨位置/轮次共享，w=0、b=logit(.95)。
原DiscoLoop的g读取未归一化软词嵌入v，初值.99；q保留原RMS归一化。
模型为一个共享Transformer层、四轮、宽768、12头；attention、MLP、残差和层归一化完整保留。

复用`paper-update-gate-multihop-u95-v1`的学习门300k结果及其已在运行的1500k续训，
不重复基线训练。已有固定门/P可作为辅助参照。此前四方案的排序是研究优先级，
不是已测的真实大模型性能排名；本次也不是预训练语言模型实验。

## 配对与预算

沿用原40000样本图、43000查询、初始化/样本流/dropout种子、batch512、lr1e-4、
warmup2000、wd.1、答案与EOS监督及原评测。原300k之后学习率保持常数，
因此新预算不改变前300k的日程。配置固定原数据哈希和原配方哈希，十二个核心源文件逐一核对。
新增一臂1500000科学更新。保存所有旧节点，并从400k至1500k每100k评测保存。
主指标固定1500k/R4图B三跳答案准确率；300k为预先指定的中间配对比较。
保留全部11池、答案+EOS及终点R1–4，不按最佳节点或轮数挑结果。

所有块和再编码仍然计算；共同门控不自动减少FLOPs。参数总量与旧学习门相同。
报告数据曝光、矩阵FLOPs和真实耗时；单图/初始化及跨机器运行差异限制结论。
