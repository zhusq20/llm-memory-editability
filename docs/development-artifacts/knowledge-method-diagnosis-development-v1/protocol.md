# Qwen 现有知识更新方法：原方法移植开发

冻结日期：2026-10-21 UTC。用户在本次会话明确要求先核查、实测已有方法，并允许在现有 Qwen 上并行实验。本文记录这一轮；不是旧 M3 或 E3 的追加训练。

## 研究问题与判读

**只用各段文档生成的单跳问题更新模型，能否改善没有参加训练的自然多跳问题，并保住旧能力？** 先做原方法的关键比较，再解释成功与失败。这个开发批提供方法在 Qwen3 上的行为证据；不会用失败直接推断 Transformer 架构不可能实现知识复用。

依据是 [Prompt Distillation 原文](https://arxiv.org/html/2412.14964v2)及[作者代码](https://github.com/kallekku/prompt-distillation)，提交 `2b72919a0836f97115f0396ee753bd284c8d91d6`。原文在 Qwen2.5 的 HotpotQA 上按段生成问题，测试原始多跳问题。旧 M3 使用模板问题、贪心答案和全参数更新，不是此原实验。

## 数据与四臂

使用作者发布的 `datasets/hotpotqa.csv` 前32题、所有已发布段落。核对发现31题各10段，第28题只有2段，合计312段；保留原数据，不补段、不换题。每段生成30题，共9,360条。作者CSV没有原始HF ID，使用CSV零基行号标识案例。独立样本单位是32个案例，不能把9,360条训练问答当独立测试案例。

问题生成只见当前段落，使用作者提示、温度1.5，每次至多取5题；原始测试问题从不进入生成提示，完全相同的问题文本排除并记录，不利用测试答案筛选。问题可能覆盖相同事实，数量不代表独立知识量。同一问题分别生成 PD 温度1.5和 SFT 温度0.25的上下文教师答案，最长512新token。截断答案保留并标记，不额外教EOS。生成失败、原始输出、重试和完整覆盖都保留；未完成全部9,360条不能进入训练。

生成批量为32，训练批量仍为4。正式准备开始前从工程默认8调整到32以提高生成吞吐；单独核验该形状的生成显存。它改变随机采样的分组及种子序列，不改变段落、问答数量或各臂共享数据的约束；工程产生的文本不进入科学训练。

| 臂 | 训练目标 | 可更新参数 | 回答的问题 |
| --- | --- | --- | --- |
| `pd_lora` | 看文档教师→不看文档学生的 KL(教师‖学生) | LoRA | 论文蒸馏配方在现有模型上能否迁移到未训练多跳 |
| `sft_lora` | 低温教师答案的闭卷 CE | 同一 LoRA 范围 | 与论文 SFT 配方比较 |
| `sft_full` | 同一批 SFT 答案 CE | 全部参数 | 固定数据和预算时，参数约束是否影响迁移与保持 |
| `sft_down` | 同一批 SFT 答案 CE | 各层 MLP down projection | 同上，比较限制写入输出投影的效果 |

**PD与SFT同时改变损失和教师答案采样温度，是整套原配方比较，不能把差异全部归因于软标签。** 后三臂固定训练数据与更新次数。共同学习率是受控配方，不是各方法分别调优后的能力上限。仅训练down projection是本项目对照，不冒称ROME、MEMIT或Cortex的原方法。

## 模型、优化与成本

现有 `Qwen/Qwen3-1.7B`，revision `70d244cc86ccca08cf5af4e1e306ecf908b1ad5e`。统一Qwen系统提示、关闭thinking、FP32参数及BF16 autocast；保持原Transformer和聊天接口。

- LoRA：r=1024、alpha=2048、dropout=.05，目标 q/k/v/o/gate/up/down 和 lm_head；不合并adapter，保留tied embedding下的独立LoRA增量。
- AdamW，lr=1e-5、weight decay=.1，前100步线性warmup，之后线性下降，梯度范数上限1。
- 每臂batch4、5轮，11,700次优化调用，46,800条样本曝光；四臂46,800次优化调用。第一步lr=0与作者代码一致。每条样本token数和教师额外前向另计，不能称相同计算量。
- KL温度2，无T²系数；每例答案token均值，再batch均值。SFT与作者一致按batch内有效答案token平均。
- 启用gradient checkpointing；每轮（2,340步）保存参数、优化器和RNG，终点保存可独立重载的训练参数。工程短测发现共享存储的大权重写入耗时明显，因此在正式启动前把恢复保存频率从500步改为每轮；不改更新预算和训练数据。输入超过8,192 token直接报错，不静默截断。
- 记录真实训练参数、曝光、有效答案token、教师/学生前向token、墙钟和显存；本轮不据更新次数宣称计算效率优势。

## 评价

对全部32题同时报告更新前/后的闭卷生成，以及提供全部原文档的生成。后者是完整文档上下文参照，不是实际检索系统，也不保证是模型成绩的严格上界。自然问题可能在预训练中见过，分别报原本正确和原本错误子集及覆盖，不能把全部题称作新知识。

每条生成保留原始文本和token。主评分采用Hotpot风格标准化EM/F1；使用统一“只回答答案”提示、温度.25、top-k50、top-p1，最多512token。没有沿用原论文的LLM判分，因此不直接比较数值。格式失分可事后另列人工审阅，不改主评分。32题配对计数为主要输出，不从小样本排名宣称普遍优劣。

旧能力复用知识调用批的全部自然问题集合，重跑更新前基线并使用原有实体别名评分；贪心生成，最多64token。单列“原本答对且更新后仍答对”的分子/分母，避免新答对补偿旧遗忘。该集合曾用于旧项目开发，是已观察保持集；不声称覆盖通用能力。训练不使用这些保持题或答案，本轮也未加入Tulu正则化。

辅助诊断固定取训练文件中每个案例的第一条问答，共32条，更新前后在闭卷teacher-forced条件下报告本臂教师答案的NLL和下一token符合率（含有效token和EOS计数）。这衡量对训练目标的拟合，不称真实事实正确率，也不用来筛选案例、早停或调整配方。PD/SFT教师答案不同，此项不能用来直接排名两种方法的事实掌握。

四臂都在全新进程重载权重后评价；另一个全新进程核对终点权重哈希和固定两条序列的逐token贪心结果及指定logit切片。该审计验证序列化一致性，不代替全量行为评价。

本轮只检验一个自然任务的单跳→多跳迁移。后续需要固定新事实、多个未训练用途、事实修改与连续写入，才能支持部署期通用知识复用；这些不自动追加到本批预算。

## 与原实验的明确差异

这是**方法移植开发**，不是原论文完整数值复现：Qwen3-1.7B替代Qwen2.5；32题替代1,000题；HF生成替代vLLM；master参数FP32和BF16算子；统一有效token attention mask；恢复学生训练模式以启用配置的LoRA dropout；生成长度明确限制512；回答评分和提示如上。作者代码的答案长度限制未传给生成器、KL未执行附录总长截断等问题不悄悄照搬。数据生成的seed修复、真实段数和排除重复测试问句均留在来源记录中。

这不是完整方法×参数范围的交叉矩阵，也没有假装已经找到每臂最优学习率。原作者代码、许可、CSV及来源哈希与本批工程源码分别保存。

节点 `sn4622128200`：GPU3准备数据并执行PD，GPU6顺序执行两条SFT LoRA/down，GPU8执行全参数SFT；同时最多三条科学训练。共享GPU锁和实际进程/容器准入检查，不抢占其他项目。每容器10 CPU、128GiB，模型缓存和冻结源码只读，输出写持久批目录。

追踪：`zsqzz/llm-memory-editability`，group为批次名；prepare与每臂训练、评价均记录。训练完成、重载通过和W&B云端独立核验分开报告。启动器仅允许一次提交，失败不自动重复启动；恢复须先检查controller、源码和实际容器。不得仅依据文档重新运行旧批次。

四臂结束后自动汇总持久目录的 `report.md` 与 `summary.json`：闭卷/上下文前后EM、旧正确问题保持的分子分母、拟合诊断及成本。未完成或审计失败的臂不记为完成，不重评分、不筛案例。

启动前必需：来源与完整配置、数据/监督/参数/重载单元契约、固定镜像验证、全尺寸模型工程短测及独立重载。启动结果与当前进度写入持久目录，并在结果汇总登记；本协议不预填科学结果。
