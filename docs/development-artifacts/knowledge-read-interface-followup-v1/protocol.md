开发批留下两个问题：

- **U3（新事实作第二跳）为什么失败？** 在注入模型的桥位置补上显式h的状态，U3可恢复到.63–.94，但只在约第16层之前补才有效。这说明新事实由早中层的显式主语表示触发；它不能区分两种解释：桥实体形成太晚（C），或桥实体已形成但形式与新事实绑定的形式不符（B′）。MEMIT把事实写进了主语表示，U3仍为0。
- **U2（新事实作第一跳）失败是否由写入位置造成？** “MEMIT可用、SFT不可用”同时改变了写入方法与写入位置，且MEMIT只覆盖14–35条筛选后的事实。

## 第1项：桥实体读出（零训练）

**对象：** 原模型与开发批已保存的注入模型（M1、M2、M3、M5、M4），两个模型，开发集与第二事实集。分析单位是事实；注入模型只统计已写入（U0生成正确）的主事实，M4同此。

**源状态（逐层，取解码层输出）：**

- **桥状态：** U3提示（两个模板，直接回答格式）中国家名C末token的状态。这与开发批T3的修补位置相同。
- **末位置状态（描述性）：** U3提示最后一个提示token的状态。
- **显式状态（对照）：** U0提示“What is the R of h?”中h末token的状态。

**三种读出（同层修补）：**

- **(a) 身份解码：** Patchscopes身份提示`cat -> cat / 1135 -> 1135 / hello -> hello / x ->`，把源状态放在x处，贪心生成8个token，看第一行是否给出h、C或v。h与C同名的事实（如Kuwait City/Kuwait）不计入(a)。原模型也做，用来看自然的桥实体形成。
- **(b) 功能互换：** 为每条事实f选另一条同关系事实g（主语、国家、取值都不同，固定种子）。把源状态放进g的U0问句“What is the R of g?”中g的末token，用教师强制贪心匹配看注入模型是否改答f的取值v。
- **(c) 回补：** 在同一U3提示中，把第s层状态写回第t层（s>t，每2层网格），位置分别为桥位置与最后提示位置。主层对在10条校准事实上选定（命中率最高，平局取层距较小者），主事实只报该层对；全网格最大值只作描述。

**预定判读（看结果前固定，开发规则，不作显著性门槛）：**

- **T\*：** 开发批T3同层曲线（主事实、已写入）中，命中率≥其最大值50%的最后一层。
- **h出现：** 某层显式解码率≥.5，且桥状态解码出h的比例≥同层显式解码率的50%。最早满足的层记为l_h。
- **回补救回率：** (回补命中率−未修补U3命中率)/(1−未修补U3命中率)，取两种位置在各自主层对上的较大者。

| 判读 | 条件 |
|---|---|
| C 形成太晚 | 不存在l_h≤T\*，存在l_h>T\*；且回补救回率≥.25 |
| B′ 形式不符 | l_h≤T\*；且在≤T\*、显式互换命中率≥.5的层上，桥互换命中率都低于显式互换命中率的50%；且回补救回率<.25 |
| 桥位置无h | 任何层都未满足“h出现” |
| 未归类 | 其它情形 |

**有效性：** 若某模型的显式解码率在所有层都<.5，(a)对该模型无效，只报(b)(c)。
