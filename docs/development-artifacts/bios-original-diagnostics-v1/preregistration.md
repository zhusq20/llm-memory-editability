# bioS 既有端点的属性与操作诊断

本轮只评价已完成的10k开发模型，不训练或更新权重。两个既有世界，各固定随机抽取开发集12个完整伙伴对（24人），全部端点使用相同人物。规范问法view 0与既有留出问法view 1分别报告。选择只依赖人物真值与固定seed，不依据旧结果或模型成功率。此小样本是开发诊断，不代表全体人物。

12个任务端点比较月份奇偶与双人出生日期比较的四种方式：直接回答、Explain briefly、oracle规则调用、自主日期提取后规则调用。前两项沿用原任务prompt；只有MP-CoT训练过Explain briefly。规则调用精确沿用既有rule_rows提示：`Question: Is {month} an even-numbered month?\nAnswer:`及`Question: Which date is earlier, {dateA} or {dateB}?\nAnswer:`。oracle填真值日期/月份，自主模式填同一端点在相同view下生成的日期。解析失败保留原文填槽、不补真值、不删除案例；全部端到端和可解析/提取正确子集分别报告覆盖与正确数。自主阶段月份解析和日期到姓名映射是主机确定性处理，明确不当作模型推理。

日期比较规则只要求模型输出所给两个日期之一，不包含姓名；输出按唯一匹配映射回原题中对应姓名，同日或不匹配均记映射失败。并列报告直接/CoT姓名是否属于题中两人，规则输出日期是否属于两个输入日期。故oracle比较测试的是日期比较规则，不证明模型会将日期绑定回真实姓名。规则prompt变化本身也是解释边界；oracle失败不能单凭此定位事实知识缺失。另列依据自主提取日期由主机正确运算的参考成绩，标为symbolic，不计入模型结果。

六个QA适配端点及十二个任务端点各进行独立重载抽样审计。按旧评价顺序选dev/test首个样本所在的完整物理batch（48例），保持原batch行与顺序、原96 token生成上限。严格比较生成、EOS、原答案正确性；同精度完整答案logp最大绝对差容忍1e-4，偏差全部保留并报告，不改旧结果。抽样审计不代表全部评价逐例重跑。

冻结plan.json含样本、checkpoint来源哈希、数据/tokenizer/实现哈希及审计原始batch；现用三个bioS实现须与原execution-source逐文件相同。FP32参数，BF16 autocast，TF32，eval，无梯度。新诊断batch=16；audit保留48。共享物理GPU5，进程allocator上限0.045；不终止他人进程，记录峰值显存与实际耗时。首次执行前CPU16项测试及ruff通过。失败与原始生成均保留。本轮不新增year或城市oracle任务：工作城市已经在BIO中，不能称未见两跳。
