完整日期真值正确子集也另报：MP规范41/48覆盖、其中41/41最终奇偶正确；MP留出28/48覆盖、其中28/28正确；MP-CoT留出7/48覆盖、其中7/7正确。完整日期正确是比月份奇偶实际所需信息更强的条件，不能用该覆盖率替代月份掌握率。

日期比较发现了更基础的前提问题。全部6条件在两个问法下，直接、CoT、oracle规则、自主规则均0/48。oracle已经提供真实日期，并使用原训练的精确日期比较prompt；模型仍全部输出不属于输入日期对的第三个日期。规则阶段没有人名，最终日期到姓名的对应由主机处理，所以这一oracle失败不能只归因于姓名绑定。与此同时，直接/CoT也没有输出题中任一姓名，原端到端失败不能被笼统解释为纯日期计算错误。

据首端点结果事后增加的[已见规则补测](rule-replay-followup.md)显示：12个端点均正确回答全部12个月份规则和24个训练日期对。也就是说，训练日期对拟合成功，但这些训练未建立对新日期对的操作泛化。该诊断不支持把原日期比较0%直接归因于知识存储或提取与组合之间的接口。若继续日期比较，需要先以更丰富的独立日期对建立并验证操作泛化，再解释依赖人物知识的比较成绩；本轮没有开展该新增训练。

审计18/18通过：共1584行按原物理batch48重放，生成文本、EOS、正确性均完全一致，完整答案logp最大绝对差为0。主诊断4608行、日期提取576行；规则补测432行。主诊断端点计算耗时合计186.8秒，峰值已分配显存0.688GB；共享物理GPU5，allocator上限0.045。以上时间不含进程外准备与前置哈希核验，不代表独占GPU速度。

诊断改变了原任务的提示、分步调用和主机处理，结果说明特定调用流程的效果，不能单独证明原模型自然计算经过相同路径。两个世界的小型开发子集、重复问法和交换顺序的伙伴题均不能视作独立大样本；此次不作总体统计推断。原实验权重、评价与历史结果未改动。
