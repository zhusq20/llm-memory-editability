# LLM Memory: Learning and Editability

**研究学习顺序如何塑造 MLP 知识表征，并影响学习效率与后续可编辑性。**

核心问题：让模型现在更容易学会的知识组织，是否也让它以后更容易更新？允许共同改善、选择性获益、取舍和零效应。

理论与实验统一维护在 [实验协议 v2.2](docs/experimental-protocol.md)。理论只保留三部分：

1. **知识形成：** 用可学习的简化门控 MLP 研究顺序如何改变共享特征与成员差异；这是主要待证问题。
2. **学习效率：** 分析激活重叠与目标方向何时促进迁移、何时造成干扰。
3. **知识编辑：** 从真实 MLP 输出权重的条件性关系出发，分析共同修改、个别修改与旧知识保持。

简化模型负责推导，真实 GELU／SwiGLU 层负责验证。不展开通用响应矩阵、容量界、样本复杂度或最优课程理论。首轮固定事实、表述和累计曝光，只交换结构事实与具体事实的学习顺序。

## 模型与数据

| 用途 | 确定采用的模型 | 确定采用的数据 |
| --- | --- | --- |
| 主机制实验 | 从头训练的 GPT-2 式自回归 Transformer：8 层、宽度 768、12 个注意力头、MLP 宽度 3072 | 自建 **SharedOrg-v1**：4096 人、128 个组织、8 个默认属性、4 个个人属性，共 54,272 条基础事实 |
| 已有 LLM 上的知识适应主验证 | **`Qwen/Qwen3-1.7B`**，主实验关闭 thinking | **SharedOrg-NL-v1**：同一事实表的英文自然语言版本，使用聊天问答监督学习旧知识，再编辑 |
| 同规模跨家族复现 | **`HuggingFaceTB/SmolLM2-1.7B-Instruct`** | 相同 SharedOrg-NL-v1、配对目标与评价标准 |
| 机制测量校准 | 同一个 8 层 Transformer | **GrokkedTransformer composition**：使用作者的 2000 实体、200 关系生成器 |
| 真实知识外部验证 | 未经世界适应的 Qwen3-1.7B 与 SmolLM2-1.7B-Instruct | **RippleEdits**：作者发布的 4755 个案例，按旧知识替换与知识新增分别评价 |

两个课程从同一初始化或官方 checkpoint 出发。Qwen 固定关闭 thinking；SmolLM2 复现相同的组内检验。模型 revision、训练契约、通用回放及能力保持评价见协议。

本轮覆盖受控语言模型训练和已有 LLM 的问答监督知识适应，不据此推断完整预训练或强化学习流程的效果。

结果分开回答：**相同预算学会多少、达到同一知识标准花费多少、随后完成同一更新花费多少。** 保留完整曲线与未达标运行；固定预算比较和知识水平相近的条件分析分别报告。

更新实验对两个课程施加完全相同的目标，比较一致更新与独立例外。单层输出权重校准、完整 MLP／全参数编辑及等预算分支干预检验原因。主评价使用完整答案自由生成，分别记录直接目标 E、必要传播 D 和旧知识保持 U；层内公式不替代行为结果。

## 当前状态

条件性学习与编辑关系已写入协议，学习顺序如何形成表征仍待推导。正式数据、训练、组织测量和 LLM 编辑流程待实现；尚未下载权重或执行正式实验。

协议已补充 2025–2026 年相关论文的数据构造依据（§4.6）、生成器与自然语言审计（§4.7）、频率及组织默认诊断基线（§8.5）。当前先实现这些契约，再检验学习顺序是否形成在共同巩固后仍存在的因果复用差异。未见组合、文档表述和较弱例外更新列为后续独立设计，首轮矩阵保持不变。

先完成普通 Transformer 开发闭环，尽早验证 Qwen，再锁定确认矩阵、完成 SmolLM2 复现与外部验证。理论推导并行推进。

仓库已有 NumPy 示例与小型 MLP／Transformer 分类器，仅用于工程检查。旧研究备忘录和临时理论综述已合并删除，不并存多份计划。

## 开发

需要 Python 3.10 或更新版本。以下是现有工程检查的 CPU 安装方式：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[neural,dev]'
python -m pytest
ruff check .
ruff format --check .
```

现有示例入口为 `memory-editability` 和 `memory-editability-neural`。正式实验的 GPU 环境与依赖将在实现时锁定版本；目前的安装命令不包含后训练 LLM 的训练环境。

代码位于 `src/llm_memory_editability/`。开发与实验记录要求见 [CONTRIBUTING.md](CONTRIBUTING.md)。研究问题、执行决策和文献依据统一维护在实验协议中，不并存旧版计划。
